# 通用 FEM 后处理平台技术文档

**文档版本：** 1.0  
**更新日期：** 2026-05-27  
**适用范围：** ODB 可视化服务（src + viewer）

---

## 一、项目背景与应用需求

### 1.1 行业背景

有限元分析（FEM）已广泛应用于结构强度、模态、稳定性等工程仿真领域。大型工程结构的精细化仿真模型规模持续增长，典型模型包含百万至千万量级节点，多工况载荷步与帧序列，以及多实例装配体坐标系。

仿真结果（ODB 文件）承载了完整的几何拓扑与物理场数据，是结构验证与设计优化的核心依据。

### 1.2 现有问题

面向 Abaqus ODB 格式的后处理，现有工具面临以下工程限制：

- **许可证依赖**：主流后处理工具（Abaqus CAE、HyperView）均需昂贵的商业许可证，制约了跨团队协同访问能力。
- **大规模数据处理能力不足**：桌面客户端在处理千万节点、多帧结果时响应缓慢，难以满足实时交互要求。
- **非线性大变形显示局限**：对几何非线性分析（nlgeom=True）结果，现有工具缺乏自动识别并在变形显示中强制比例因子为 1 的机制。
- **跨平台访问受限**：桌面工具无法直接提供面向浏览器的轻量访问接口，不利于方案评审与多端查阅。

### 1.3 建设必要性

针对上述问题，构建一套面向通用 FEM 后处理需求的 Web 化服务平台，实现 ODB 仿真结果的无许可证浏览器交互访问，是提升工程仿真效率、降低使用门槛的必要举措。

## 二、数据对象与场景分析

### 2.1 数据对象

平台处理的核心数据对象为 Abaqus ODB（Output Database）文件，其主要特征如下：

| 维度 | 典型规模 |
|---|---|
| 节点数量 | 10 万 ～ 1000 万 |
| 单元类型 | 壳单元、实体单元、梁/杆单元、质量点 |
| 装配实例数 | 1 ～ 数十个（各实例含独立坐标变换矩阵） |
| 载荷步数 | 1 ～ 数十步（STATIC、FREQUENCY、DYNAMIC、BUCKLE） |
| 帧数 | 每步 1 ～ 数十帧，总帧数典型值约 30 帧 |
| 结果字段 | 位移（U）、应力（S）、应变（E）、反力（RF）等，含 NODAL / ELEMENT_NODAL / INTEGRATION_POINT 三种数据位置 |

### 2.2 支持的单元类型

平台支持 Abaqus 常见单元族：

- **壳单元**：S3、S3R、S4、S4R、S4R5、S6、S8R、S8R5、STRI3、STRI65
- **实体单元**：C3D4、C3D6、C3D8（及 R/H/I 变体）、C3D10、C3D15、C3D20（及变体）
- **梁/杆单元**：T3D2、T3D3、B31、B32、PIPE31、PIPE32（线单元，渲染为线框）
- **质量点**：MASS、ROTARYI（点单元，渲染为点云）
- **平面/轴对称单元**：CPS3/CPS4、CPE3/CPE4、CAX3/CAX4（按壳面处理）

高阶单元（C3D10、C3D20、S8R 等）在渲染层仅使用角节点，完整高阶连接关系另存于 `_highorder.h5`，保留精确数据。

### 2.3 典型处理场景

- 大型结构静力分析结果（多工况、多帧位移/应力云图）
- 线性/非线性模态分析结果（振型动画、频率查阅）
- 屈曲分析特征模态显示
- 含大变形（nlgeom）的几何非线性分析（强制变形比例因子为 1）
- 多实例装配体（含坐标变换的集成模型）

## 三、系统总体目标

建立面向通用 FEM 仿真结果的 **Web 化、无许可证、交互式后处理能力**，实现从 Abaqus ODB 文件到浏览器三维云图交互的全流程数据贯通，具体能力目标如下：

1. **几何还原能力**：忠实还原 ODB 中的装配体几何，支持多实例、坐标变换、多单元类型混合模型的正确表面提取与三角化。
2. **结果场映射能力**：将任意帧的结果字段（含多分量张量场）映射为顶点着色，支持平滑着色与平面着色切换，提供准确图例区间。
3. **大规模实时渲染能力**：面向千万节点量级模型，通过预处理索引几何与 GPU 渲染，实现流畅帧率的三维交互浏览。
4. **空间查询能力**：支持单元/节点级精确拾取（Pick）与包围框选择（BBox Select），获取指定位置的结果数值。
5. **模态动画能力**：支持频率分析振型的实时谐波动画播放。
6. **截面查看能力**：支持任意切面截图，获取模型内部结果分布。

## 四、系统总体架构

平台采用三层流水线架构，前后端分离，各层职责明确、数据单向流动：

```
ODB 文件
    │
    ▼
┌──────────────────────────────────────────────────────┐
│  L1 — 忠实提取层                                      │
│  abaqus_dump.py（Abaqus Python 2.7）                  │
│  l1_pack.py（Python 3 / h5py）                       │
│  输出：HDF5 几何/结果文件 + manifest.db              │
└─────────────────────┬────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────────────────┐
│  L2 — 预处理层                                        │
│  ingest.py（Python 3 / NumPy，一次性离线计算）        │
│  输出：渲染就绪索引几何 + 特征边 + 八叉树             │
└─────────────────────┬────────────────────────────────┘
                      │
                      ▼
┌──────────────────────────────────────────────────────┐
│  L3 — 服务层                                          │
│  FastAPI + Gunicorn 多 Worker                         │
│  读 L1 HDF5（结果）+ L2 HDF5（几何）                 │
│  注册表轮询（每 10 s）                                │
└─────────────────────┬────────────────────────────────┘
                      │  HTTP + L3BE 二进制协议
                      ▼
┌──────────────────────────────────────────────────────┐
│  前端 — Three.js 浏览器查看器                         │
│  Vue 3 + Three.js + three-mesh-bvh                   │
│  ODB 列表 / 云图控制 / 拾取 / 动画 / 截面            │
└──────────────────────────────────────────────────────┘
```

**数据流向：**  
ODB → L1 HDF5（一次，含 Abaqus 许可证）→ L2 渲染缓冲（一次，纯 Python）→ L3 按需读取并响应前端请求 → 浏览器实时渲染。

L1 提取完成后，L3 服务运行**无需 Abaqus 许可证**。

## 五、功能模块设计

### 5.1 L1 提取模块（`src/l1/`）

**工程目标**：忠实提取 ODB 中全部几何与结果数据，不做任何裁剪或坐标变换，保留原始精度，供后续层使用。

**两阶段实现**：

- **Phase 1 — abaqus_dump.py**：运行于 Abaqus Python 2.7 环境（需许可证），调用 `odbAccess` API 读取 ODB，将节点坐标、单元连接关系、结果字段以 `.npy` 中间格式写入磁盘。支持并行实例提取，实时刷新进度（行缓冲 stdout）。
- **Phase 2 — l1_pack.py**：运行于标准 Python 3 环境，将 `.npy` 中间文件打包为 HDF5 文件集和 SQLite 路由表（manifest.db）。支持结果分组（result_group）追加模式，允许多批次导入同一几何的不同工况结果。

**输出结构**：

```
workspace/
  l1/
    assembly.h5              — 实例变换矩阵、装配集
    geometry/<inst>.h5       — 节点坐标、角节点连接
    geometry/<inst>_highorder.h5  — 完整高阶连接
    sets/sets.h5             — 节点集/单元集成员关系
    results/<step>__<field>.h5    — 多帧结果 [num_frames, N, ...] 布局
  manifest.db                — 路由索引（实例、步骤、帧、结果文件路径）
```

**关键设计**：结果以 `[num_frames, N, ...]` 多帧 HDF5 布局存储，支持单次 IO 读取任意帧切片，也支持读取单节点时间历程。

---

### 5.2 L2 预处理模块（`src/l2/`）

**工程目标**：将 L1 原始数据转换为渲染就绪缓冲，建立空间索引，所有运算一次完成，L3 服务运行期间只读。

**核心计算步骤**：

1. **全局坐标变换**：将各实例局部节点坐标乘以装配变换矩阵，得到全局坐标 `[N, 3] float32`。
2. **表面提取**：面被恰好一个单元拥有（边界面）的即为表面面，采用向量化哈希实现，壳单元所有面均为表面。
3. **三角化**：三角形直通，四边形对角线劈分，高阶多边形仅使用角节点，全程 NumPy 向量化。
4. **索引几何构建**：生成 `positions [Nv, 3] float32` + `indices [Nt, 3] int32` 的索引格式，共享顶点（同一单元面内），法线由前端 `computeVertexNormals()` 计算，节省传输带宽。
5. **特征边提取**：边界边（仅属于一个三角形）和折叠边（相邻面法线夹角 ≥ 30°）构成特征边集，线框叠加显示。
6. **八叉树构建**：最大深度 8、叶节点面数 ≤ 1000，供 L3 包围框查询做空间粗筛。

**输出**：L2 HDF5 文件（render.h5）及 manifest.db 路径更新，L3 启动时加载到内存。

---

### 5.3 L3 服务模块（`src/l3/`）

**工程目标**：以 HTTP 服务形式按需提供几何与结果数据，支持多 ODB 并发访问，保障读取并发安全性。

**服务架构**：

- **运行时**：FastAPI + Gunicorn 多 Worker 模式，Worker 通过 copy-on-write 共享预加载的内存索引，减少重复内存占用。
- **内存注册表（ModelIndex）**：每个 ODB workspace 对应一个 `ModelIndex` 实例，持有全局坐标 `coords_global`、拾取映射 `render_source_elem_row`、顶点-节点行映射 `source_node_rows`、八叉树 `octree`、结果均化数据等，预 fork 加载，Worker 只读共享。
- **注册表轮询**：独立 daemon 线程每 10 秒扫描 `registry.db`，热加载新就绪的 ODB，无需重启服务。
- **嵌入式 Runner**：可选将 job_runner（L1/L2 管线）作为后台线程嵌入 app.py，Linux 环境默认开启；Windows 环境默认关闭，需独立进程运行。

**主要 API 端点分组**：

| 分组 | 功能 |
|---|---|
| `/api/odb/{id}/geometry/` | 几何渲染缓冲（indexed format，分块传输） |
| `/api/odb/{id}/results/frame-colors` | 结果着色（uint8 RGBA，逐顶点） |
| `/api/odb/{id}/results/frame-scalars` | 结果标量值（float32，前端自定义色表） |
| `/api/odb/{id}/results/frame-deformed-positions` | 变形后顶点坐标 |
| `/api/odb/{id}/query/pick` | 单元/节点拾取，返回精确结果值 |
| `/api/odb/{id}/query/bbox` | 包围框选择，返回命中实例列表 |
| `/api/odb/{id}/meta` | 实例、步骤、帧、字段元数据 |
| `/api/odb/{id}/section/` | 截面切割几何与结果 |
| `/api/odb/{id}/modal/` | 振型数据与谐波动画帧 |
| `/api/projects/` | Project 模式的 ODB/INP 提交与状态查询 |

---

### 5.4 前端查看器（`viewer/`）

**工程目标**：在浏览器中实现大规模 FEM 模型的实时三维交互后处理，无需安装任何客户端软件。

**核心组件**：

- **ThreeViewport.vue**：Three.js WebGL 渲染主视口，管理场景对象（几何 Mesh、特征边线框、梁/杆线单元、质量点云）、轨道控制（旋转/平移/缩放）、着色属性同步、截面裁剪面。
- **BVH 加速拾取**：集成 `three-mesh-bvh`，所有 `BufferGeometry` 自动启用 BVH，单次点选查询时间复杂度 O(log N)，框选配合八叉树粗筛实现大规模模型下的响应拾取。
- **OdbListCard.vue**：ODB 列表管理，连接服务端，切换当前激活 ODB 与结果分组。
- **ColorsCard.vue / ColorCodeCard.vue**：结果字段选择（步骤/帧/分量），触发后端渲染着色请求，解析 L3BE 二进制载荷并更新顶点颜色属性。
- **LegendCard.vue / LegendEditor.vue**：色条图例显示与区间自定义编辑。
- **DeformCard.vue**：变形显示控制（比例因子、非线性大变形锁定）。
- **PickCard.vue / ProbeTableCard.vue**：拾取结果详情展示与多点探针表格。
- **ViewCutCard.vue**：截面切割控制（轴向、位置、填充面/截面边显示）。
- **Modal 动画**：支持两种模式—GPU 着色器模式（实时谐波动画，无需逐帧请求）和 CPU 预计算模式（预取所有帧缓冲后逐帧推送 GPU）。

**前端状态管理**：Pinia store（`viewer.js`）集中管理连接地址、激活 ODB ID、结果分组、鼠标模式、探针数据、状态栏信息。

## 六、关键技术

### 6.1 二进制载荷协议（L3BE）

**背景**：大规模 FEM 模型单帧着色数据量可达数百 MB（千万三角面 × RGBA），JSON 序列化开销不可接受。

**难点**：多种数组类型（float32、int32、uint8）需混合打包，前端须无歧义解析各段边界与数据类型。

**技术路线**：设计固定头部的二进制信封格式（L3BE），每段包含名称、dtype、shape、数据体。服务端用 NumPy `tobytes()` 序列化，HTTP Content-Type 设为 `application/octet-stream`；前端 JavaScript 按固定解析逻辑读取 `ArrayBuffer`，重建各命名数组。GZip 中间件对响应自动压缩（阈值 1000 字节），有效降低传输量。

**形成能力**：单次 HTTP 响应携带几何、颜色、图例等多段数组，避免多次往返，支撑千万面级模型的交互帧率。

---

### 6.2 预处理索引几何与表面提取

**背景**：ODB 存储的是完整体网格或壳网格，渲染只需可见表面，且需满足 GPU 的三角面约束。

**难点**：大型模型的面-邻接关系计算（判断哪些面是外表面）若逐面遍历，时间复杂度为 O(N²)。混合单元类型（壳+实体+高阶）的三角化规则各异，高阶单元退化为线性表示需保证拓扑正确。

**技术路线**：L2 ingest.py 用 NumPy 向量化实现全部计算：将所有单元面的排序顶点标签组合成哈希键，统计出现次数，出现一次的即外表面（对实体单元）；壳单元所有面均计入。三角化采用 NumPy 切片广播，避免 Python 循环。高阶单元只取角节点索引（前 N_corner 列），丢弃中节点，几何误差在工程允许范围内。

**形成能力**：百万量级单元模型的预处理在分钟级完成，输出紧凑索引几何，渲染内存显著低于 Triangle Soup 格式。

---

### 6.3 BVH 加速空间查询

**背景**：拾取操作需要在鼠标点下方的所有三角面中找到最近命中面，大型模型三角面数达千万量级。

**难点**：Three.js 原生 Raycaster 对每个 Mesh 做 O(N) 线性遍历，千万面级模型单次拾取耗时超过 1 秒，交互不可接受。

**技术路线**：集成 `three-mesh-bvh` 库，在几何加载后调用 `geometry.computeBoundsTree()` 构建 BVH 层级包围体树；重写 `Mesh.prototype.raycast` 为 BVH 加速版本。BVH 构建为一次性成本（加载时），查询时间复杂度降为 O(log N)。服务端拾取路径配合内存中 `render_source_elem_row` 映射，O(1) 将渲染面索引反查为 ODB 单元标签，再从 L1 HDF5 读取该单元该帧的精确结果值。

**形成能力**：大型模型（千万面）下单击响应时间 < 100 ms，支持框选区域（BBox Select）精确返回命中单元集合。

---

### 6.4 多 Worker 内存共享与并发安全

**背景**：生产环境 Gunicorn 启动多个 Worker 并发处理请求，每个 Worker 若独立加载 ODB 内存索引将导致内存爆炸（单 ODB 约 2 GB）。

**难点**：HDF5 和 SQLite 均为单写者约束，多 Worker 不能同时写；内存索引数据量大，不适合每 Worker 独立复制。

**技术路线**：利用 Linux `fork()` 的 copy-on-write 语义：`_bootstrap_registry()` 在 Gunicorn 主进程（pre-fork）阶段完成所有 ODB workspace 的 HDF5 读取和内存索引构建，fork 产生的子 Worker 以只读方式共享这段内存，物理页面按需复制（CoW）。L3 服务运行期间对 HDF5 和 SQLite 只读（User Sets 写入 SQLite 除外），避免多写冲突。manifest.db 写操作仅由 job_runner 单进程负责。

**形成能力**：多 Worker 并发服务单个 ODB 的内存开销等同于单 Worker，支持高并发前端访问而不成倍增长内存占用。

---

### 6.5 模态振型动画技术

**背景**：频率分析输出振型（eigenvector），需在浏览器中展示结构的谐波振动动画。

**难点**：逐帧从服务端请求变形数据引入显著网络延迟，高频动画帧率（≥ 30 fps）无法实现；前端 CPU 逐帧重算所有顶点位移成本高。

**技术路线**：
- **GPU 着色器模式**：服务端一次返回实部/虚部振型位移向量，前端写入自定义 `ShaderMaterial`，在 `requestAnimationFrame` 中仅更新时间 uniform，GPU 按 `d = Re·cos(ωt) + Im·sin(ωt)` 实时计算每顶点变形，无 CPU 参与。
- **CPU 预计算模式**：预先计算若干帧的完整顶点坐标缓冲（Float32Array），动画循环按帧顺序推送到 GPU `position` attribute，适用于着色器模式不支持的场景。

**形成能力**：振型动画以 60 fps 流畅播放，支持任意振型切换与频率调节，无需逐帧网络请求。

## 七、技术路线

```
第一步  ODB 忠实提取
        abaqus_dump.py 调用 odbAccess API，完整导出几何（节点、单元、变换）与结果（多步、多帧、多字段）
        l1_pack.py 打包为 HDF5 + manifest.db，建立路由索引

第二步  渲染缓冲预构建
        ingest.py 向量化计算：坐标变换 → 表面提取 → 三角化 → 索引几何 → 特征边 → 八叉树
        一次计算，结果持久化，L3 只读

第三步  服务层空间索引加载
        _bootstrap_registry() 预 fork 加载所有 ODB workspace 的内存索引
        注册表轮询线程持续感知新就绪 ODB，热加载无需重启

第四步  二进制协议按需服务
        前端按需请求几何/颜色/变形/振型等端点
        服务端从 L2 HDF5（几何）和 L1 HDF5（结果）读取，经 L3BE 打包后返回

第五步  浏览器实时渲染与交互
        Three.js 解包 L3BE，更新 BufferGeometry 顶点属性（位置/颜色）
        BVH 支持高性能拾取，着色器支持振型动画
        全程无 Abaqus 许可证依赖
```

上述五步形成从 ODB 原始文件到浏览器交互后处理的完整闭环：L1 承担许可证隔离，L2 承担计算密集的离线预处理，L3 承担轻量按需服务，前端承担渲染与交互，各层职责清晰，数据单向流动，不存在运行时反向依赖。

## 九、部署说明

### 9.1 目录约定

```
workspace/
  l1/        — L1 提取输出（HDF5 + manifest.db）
  l2/        — L2 预处理输出（render.h5 索引几何）
  manifest.db — 路由索引（由 L1 创建，L3 只读）
```

### 9.2 运行流程

**Step 1：L1 提取（需 Abaqus 许可证，执行一次）**

```bash
# Phase 1：Abaqus Python 2.7
abaqus python src/l1/abaqus_dump.py --odb model.odb --out /data/<odb_id>/

# Phase 2：Python 3
python src/l1/l1_pack.py --workspace /data/<odb_id>/
```

**Step 2：L2 预处理（Python 3，执行一次）**

```bash
python src/l2/ingest.py --workspace /data/<odb_id>/
```

**Step 3：启动 L3 服务**

```bash
# 开发模式
uvicorn src.l3.main:app --reload --port 5000

# 生产模式（多 Worker）
gunicorn src.l3.main:app -w 4 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:5000
```

**Step 4：访问前端查看器**

```bash
cd viewer && npm install && npm run dev
# 浏览器访问 http://localhost:5173，填写服务地址后连接
```

### 9.3 配置项（`service_config.json`）

| 字段 | 说明 | 默认值 |
|---|---|---|
| `APP_PORT` | 服务监听端口 | 5000 |
| `APP_EMBEDDED_RUNNER` | 是否嵌入 job_runner 线程（1/0） | Linux: 1, Windows: 0 |
| `DATA_ROOT` | workspace 根目录 | `./data` |
| `APP_ODB_WORKSPACE` | 开发模式直接指定 workspace 路径 | 空（生产模式） |
| `ABAQUS_CMD` | Abaqus 可执行文件路径 | `abaqus` |
