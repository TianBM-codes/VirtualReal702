# INP 通用解析策略：架构闭环参考建议 (Gemini 修正版)

## 1. 核心愿景：从“关键字解析”转向“标准模型交换”
在构建通用 INP 解析器时，真正的挑战并非对关键字的覆盖率，而是如何确保解析产物能够无缝接入现有的三层架构（L1/L2/L3）。一个闭环的策略建议将解析器定位为一个“转换桥接器”，其最终输出应在语义和结构上与项目现有的 **L1 (Faithful Dump) HDF5 Schema** 严格对齐。

## 2. 层次化流水线的逻辑推演

### 2.1 词法规范层 (The Lexical Layer)
这一层关注于输入流的完整性。技术观察表明，Abaqus 文件的物理行并不直接等同于逻辑行。
*   **续行与注释**：处理以逗号结尾的关键字续行，以及过滤行内注释（`**`），是确保后续解析逻辑简洁的前提。
*   **递归包含**：`*Include` 机制的深度优先展开，决定了解析器处理超大规模分块模型的能力。

### 2.2 作用域感知的解析层 (The Scoped Parser)
考虑到 Abaqus 的对象命名空间遵循 `Part -> Assembly -> Instance` 的层次结构，扁平化的存储方式可能导致命名冲突。
*   **合格名称 (QualifiedName)**：所有命名对象（Set, Surface, Material）若能以 `(Scope, LocalName)` 为键值存储，将天然解决多 Part 实例化时的命名冲突。
*   **声明与引用分离**：解析阶段仅记录“引用请求”，而不立即尝试查找，这为复杂的跨域引用留出了逻辑空间。

### 2.3 语义解算层 (The Resolver)
这是实现闭环的关键。该层负责将静态语法对象转化为符合 L1 规范的结构化模型。
*   **标签映射与索引构建**：保留所有原始节点/单元标签（Labels），并同步构建内部行索引（Row Index）与标签的双向映射表，确保在紧凑存储的同时，不丢失原始 FEM 语义。
*   **变换矩阵解算**：解析 Instance 的平移与旋转参数，并将其转化为标准的变换矩阵（Transformation Matrix）。**注意**：应保留节点的原始局部坐标，而非在解析阶段直接生成全局坐标，以便与 ODB L1 的处理逻辑保持高度一致。
*   **状态投影 (可选建议)**：对于多 Step 模型，考虑建立“状态继承”逻辑，计算每步生效的边界条件快照，为下游消费层减负。

### 2.4 拓扑中台 (The Topology Hub)
为了避免解析器内部硬编码单元几何逻辑，引入一个独立的拓扑知识库是高度解耦的体现。
*   **单元语义解耦**：解析 `*Surface`（如 `S1`, `SPOS`）时，通过查阅拓扑表获知对应的节点子集，而非在解析函数中编写条件分支。

## 3. 稳健性与诊断策略
通用的解析策略往往包含一套完整的诊断账目。
*   **非破坏性解析**：对于暂不支持的高级关键字或特殊的单元类型，记录为 `WARNING` 并保留原始数据流，比直接中断解析更具工程实用价值。
*   **源码追溯**：在内存模型中保留原始文件行号，能够为下游的错误定位提供精确的物理指引。

## 4. 结论
一个真正闭环的 INP 解析器，其成功标志在于：**其导出产物在 L1 HDF5 结构、标签语义及变换矩阵表示上，应与 `abaqus_dump.py` 从 ODB 抽取的产物无异。** 这种“数据保真”的设计，是实现多格式支持的最短路径。
