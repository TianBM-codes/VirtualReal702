# 模型修正功能汇报

## 1. 项目目标

本项目中，我负责的部分是“模型修正”业务链路，核心目标是把试验数据和有限元模型连接起来，为后续的参数修正、灵敏度分析和结果比对提供一条可执行的工程流程。

从模型修正逻辑来看，这条链路的业务目标可以概括为：

1. 导入有限元模型和试验模态数据。
2. 建立试验测点与有限元节点之间的对应关系。
3. 建立试验自由度与有限元自由度之间的对应关系。
4. 形成可用于模型修正的响应目录。
5. 支持对有限元参数进行灵敏度分析前的输入文件准备。
6. 调用本地 Abaqus / Nastran 执行分析。
7. 将试验模态与有限元模态进行相关性计算，为参数修正提供依据。

## 2. 当前已经实现的业务能力

### 2.1 试验数据导入

当前程序已经支持导入 `UNV` 试验模态数据，包括：

- 试验测点坐标
- 试验单元连线
- 试验模态频率
- 试验模态振型

这一步的作用，是把试验侧的频率和振型数据整理成后续可计算的数据基础。

### 2.2 有限元模型导入

当前程序已经支持导入普通 Abaqus `inp` 文件，并提取出模型修正需要的关键信息，包括：

- 材料参数候选项
- 截面参数候选项
- 节点集合与单元集合
- 全局节点坐标

这里的设计思路不是直接识别“优化参数”，而是先把可能参与修正的稳定标量提取出来，后续由业务人员选择哪些参数真正作为修正变量。

### 2.3 修正参数准备

系统已经支持：

- 从 `inp` 中抽取候选参数
- 从 `NSET / ELSET` 中抽取可选作用域
- 由“候选参数 + 集合”创建用户定义的修正参数

这一步的业务意义是，把原始有限元模型里的材料、厚度等信息，转换为后续可以被求解器修改和求导的“可管理参数”。

### 2.4 试验点与有限元节点匹配

系统已经支持：

- 基于有限元节点八叉树进行最近邻匹配
- 手动平移、旋转
- 自动刚体平移 / 旋转估计
- 保存匹配结果和变换信息

这一步解决的是“试验测点不一定和模型节点完全重合”的问题，让试验测点先落到有限元节点体系上。

### 2.5 试验自由度与有限元自由度匹配

系统已经支持把试验侧平动自由度 `UX / UY / UZ` 映射到有限元侧位移自由度 `U1 / U2 / U3`。

这一步的业务意义是：

- 节点对应之后，还要明确振型方向对应关系
- 这样后续做模态相关性计算时，比较的是同一物理方向上的响应

### 2.6 修正响应目录构建

系统已经可以构建模型修正使用的响应目录，当前支持两类响应：

- 模态频率响应
- 节点位移响应

这一步是为了把“可用于修正的观测量”统一整理出来，便于后续做灵敏度矩阵、参数筛选和结果展示。

### 2.7 有限元模态结果导入与相关性计算

系统已经支持：

- 导入有限元模态位移结果
- 基于已完成的节点匹配和自由度匹配，计算试验模态与有限元模态之间的相关性

当前程序输出的核心指标包括：

- `DAC`
- `DSF`

它们用于衡量：

- 两个振型是否相似
- 有限元振型在幅值上与试验振型的对应程度

### 2.8 灵敏度分析输入文件生成

当前程序已经具备两类 Abaqus 输入文件改写能力：

1. 普通材料参数灵敏度分析
   - 从普通 `inp` 中识别材料弹性模量和泊松比
   - 自动生成 `designParameter.inp`
   - 自动生成 `*_sensitivity.inp`
   - 在静力分析步中插入 DSA 和 Design Response

2. 壳厚度 Adjoint 灵敏度分析
   - 自动识别 `Shell Section`
   - 自动把壳厚度改写为可求导的 distribution 形式
   - 自动把静力步改成 `SENSITIVITY=ADJOINT`
   - 自动插入基本的设计响应

### 2.9 本地求解器调用

这次已经补齐了本地求解器集成能力，程序现在可以直接从后端调用：

- 本地 Abaqus
- 本地 Nastran

已支持的计算流程有：

1. Abaqus 材料参数灵敏度分析
2. Abaqus 壳厚度 adjoint 灵敏度分析
3. Nastran 模型转 `SOL103` 后执行模态分析

程序会自动完成：

- 输入文件生成
- 命令拼装
- 作业目录执行
- 输出日志截取
- 结果文件收集

## 3. DAC 和 DSF 的业务含义

### 3.1 DAC

`DAC` 用来衡量试验振型和有限元振型的相似程度。

如果把试验振型和有限元振型都看成一组复数向量，那么程序计算的是两者的归一化相关程度。数值越接近 `100%`，表示两个振型越一致。

业务上可以理解为：

- `DAC` 高：形状相似，模态对应关系可信
- `DAC` 低：形状差异大，不适合作为同一模态对比

### 3.2 DSF

`DSF` 反映的是有限元振型缩放到试验振型时的幅值比例。

程序先求出一个最优比例系数，使有限元振型在整体上尽量贴近试验振型，再取这个系数的模作为 `DSF`。

业务上可以理解为：

- `DSF` 接近 1：有限元和试验的幅值水平比较接近
- `DSF` 偏离 1 较多：即使形状接近，幅值上仍存在偏差

### 3.3 当前程序中的计算逻辑

当前程序的计算步骤是：

1. 先将试验测点自由度转换成一组复数振型值。
2. 将有限元节点位移沿匹配自由度方向投影，得到有限元侧对应的标量振型值。
3. 对同一组观测点上的试验向量和有限元向量进行相关性计算。

程序中的核心公式可概括为：

- `DAC = 100 × |<test, fem>|² / (||test||² × ||fem||²)`
- `DSF = |<fem, test> / <fem, fem>|`

因此，`DAC` 主要看形状相似度，`DSF` 主要看幅值比例。

## 4. 当前功能范围

### 4.1 已覆盖范围

当前模型修正部分已经覆盖以下范围：

- 试验模态数据导入
- Abaqus `inp` 模型解析与参数候选提取
- 集合提取与修正参数定义
- 试验点与有限元节点匹配
- 平动自由度匹配
- 响应目录构建
- 有限元模态结果导入
- DAC / DSF 计算
- Abaqus 灵敏度输入文件生成
- 本地 Abaqus / Nastran 求解器调用

### 4.2 当前未覆盖范围

目前还没有完全闭环的部分包括：

- 旋转自由度 `RX / RY / RZ` 的匹配
- 更复杂噪声场景下的自动配准增强
- 由数据库中的修正参数自动回写一般 `inp`
- 自动形成“参数修改 -> 求解 -> 结果回读 -> 重新比较”的完整优化闭环
- 直接从 Abaqus `odb` 中抽取模型修正需要的模态结果并自动入库
- 自动给出最佳模态配对建议

## 5. 当前程序对业务的实际价值

从模型修正业务角度看，当前程序的价值主要体现在三点：

1. 把试验数据和有限元模型放在了同一套计算坐标系中。
2. 把“修正参数”和“修正响应”整理成了结构化对象，便于后续扩展自动修正流程。
3. 已经打通了“输入文件准备 + 本地求解器调用 + 结果相关性评价”的关键技术链路。

换句话说，当前程序已经不是单纯的数据导入工具，而是已经具备模型修正前处理和部分计算执行能力的平台雏形。

## 6. 后续建议

建议下一阶段继续推进以下工作：

1. 打通“优化参数回写 `inp` -> 调用 Abaqus -> 自动读取结果 -> 更新相关性”的完整闭环。
2. 增加旋转自由度和更复杂试验坐标系的支持。
3. 增加基于 `DAC + 频率误差` 的模态自动配对推荐。
4. 将本地求解器执行结果进一步结构化入库，便于批量比对和历史追踪。
5. 在业务层形成标准化的“单次修正分析任务”对象，方便项目管理和汇报。
