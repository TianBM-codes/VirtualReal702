## 2. 第一阶段总目标

> 顺序修正说明  
> 第一阶段总目标应明确拆成两条连续主线：  
> 第一条主线：`SOL103 -> OP2 模态 -> 模态导入/比对 -> DAC / DSF / 后续 MAC`  
> 第二条主线：`SOL103 -> SOL200 -> OP2 灵敏度 -> 灵敏度矩阵桥接`

第一阶段的目标不是“一次性把所有 Nastran 能力做完”，而是打通一条最小但完整的主链路：

1. 读取 `BDF`
2. 生成 `SOL200 BDF`
3. 调用 Nastran 求解
4. 读取 `OP2`
5. 提取模态结果
6. 提取灵敏度矩阵预览
7. 把模态结果 / 灵敏度矩阵桥接到当前项目已有结构

一句话概括：

**先证明“Python 版 Nastran 工作流能跑通”，再谈扩展参数类型、响应类型和复杂后处理。**

## 3. 第一阶段不追求的内容

为了避免范围失控，这一阶段明确不追求：

- 远程 Nastran 调度
- 一次性支持所有 `SOL200` 参数类型
- 一次性支持所有 `DRESP1`
- 一次性支持所有 `OP2` 变体
- 一次性接入完整优化闭环
- 一次性完成 `MAC` 自动计算
- 一次性完成灵敏度矩阵自动归一化

这不是放弃这些功能，而是避免第一阶段把战线拉得过长。

## 4. 第一阶段建议拆成 6 个任务包

> 顺序修正说明  
> 任务包优先级应理解为：  
> A 样本准备 -> B `SOL103` 求解 -> C `OP2` 模态解析与导入 -> D `SOL103 -> SOL200` 生成器 -> E `OP2` 灵敏度矩阵 -> F 接口与异步任务

建议把开发任务拆成 6 个任务包，按依赖顺序推进。

### 任务包 A：基础梳理与样本准备
### 任务包 B：SOL200 生成器
### 任务包 C：Nastran 求解执行
### 任务包 D：OP2 模态解析
### 任务包 E：OP2 灵敏度矩阵解析
### 任务包 F：接口与异步任务接线

下面逐个展开。

## 5. 任务包 A：基础梳理与样本准备

这是第一阶段最容易被低估、但其实非常关键的一包。

## 5.1 目标

把后续开发需要的真实样本、接口边界、可复用代码点先准备清楚。

## 5.2 需要确认的输入样本

建议至少准备 4 组样本：

### A1. 普通模态 `BDF`

用途：

- 用来测试 `SOL103`
- 用来测试 `BDF` 基础解析

### A2. 对应的模态 `OP2`

用途：

- 用来测试模态频率和模态振型提取

### A3. `SOL200` 样本 `BDF`

用途：

- 用来对照 BAS 生成结果
- 看 `DESVAR / DVPREL1 / DVMREL1 / DRESP1 / DCONSTR` 是否和预期一致

### A4. 带灵敏度输出的 `OP2`

用途：

- 用来确认灵敏度矩阵到底以什么形式存在
- 用来验证“行列标签”和“数值块”怎么取

## 5.3 这一包的核心产出

不是代码，而是这些明确结论：

1. 至少有一套能稳定复现实验的 `BDF + OP2`
2. 至少有一套 `SOL200` 输出样本
3. 至少有一套带灵敏度矩阵的 `OP2`
4. 明确第一阶段只支持哪些卡片和哪些结果块

## 5.4 验收标准

满足以下条件就算任务包 A 完成：

- 已拿到并保存至少 1 套模态样本
- 已拿到并保存至少 1 套灵敏度样本
- 已能说明每套样本的用途
- 已确认这些样本能被当前环境中的 Nastran / pyNastran 使用

## 5.5 依赖说明

这一包是后续所有任务包的前置条件。  
尤其任务包 E 基本上必须依赖真实灵敏度 `OP2` 样本，否则只能停留在“架子搭好”。

## 6. 任务包 B：SOL200 生成器

> 顺序修正说明  
> 这一包不应再理解成第一条代码主线。  
> 它现在应理解成：在 `SOL103` 模态链路已经跑通之后，再进入的“第二条主线输入生成包”。

这是第一条真正的代码主线。

## 6.1 目标

新增 Python 版 `SOL200` 生成器，支持第一阶段参数与响应。

## 6.2 建议落位

新增文件：

- `services/model_update/solver_prep/nastran_sol200.py`

## 6.3 第一阶段支持范围

参数：

- `H`
- `E`
- `RHO`

响应：

- `FREQ`

## 6.4 主要任务

### B1. 建立 `SOL200` 控制段生成函数

负责输出：

- `SOL 200`
- `CEND`
- `METHOD`
- `DESSUB`
- `DSAPRT`
- `SUBCASE`
- `BEGIN BULK`
- `PARAM`
- `EIGRL`

### B2. 建立参数中间模型

先把外部输入统一成 Python 内部结构，避免生成器直接耦合数据库。

### B3. 生成 `DESVAR`

支持：

- 初值
- 上下界

### B4. 生成 `DVPREL1 / DVMREL1`

支持：

- `H -> PSHELL`
- `E -> MAT1.E`
- `RHO -> MAT1.RHO`

### B5. 生成 `DRESP1 / DCONSTR`

第一阶段只做模态频率 `FREQ`。

### B6. 过滤或保留原始 `BDF` 中的相关卡片

这一步需要参考已有 `nastran_sol103.py` 和 BAS 的做法，避免：

- 重复 `PARAM`
- 重复 `EIGRL`
- 原始控制段和新控制段冲突

## 6.5 验收标准

满足以下条件算通过：

1. 给定最小样本 `BDF`，能生成新 `SOL200 BDF`
2. 生成结果中包含正确的：
   - `DESVAR`
   - `DVPREL1 / DVMREL1`
   - `DRESP1`
   - `DCONSTR`
3. 生成文件能被人工检查读懂
4. 用真实 Nastran 运行时，不因为卡片语法直接报错

## 6.6 风险点

- 参数目标解析不清楚时，容易把参数挂错 `PID` 或 `MID`
- 原始 `BDF` 已含 `EIGRL/PARAM` 时，处理不好会冲突
- 某些模型可能不是 `MAT1`，第一阶段要明确报“不支持”

## 7. 任务包 C：Nastran 求解执行

> 顺序修正说明  
> 如果按新的业务顺序理解，这一包在第一阶段里优先对应“已有 `SOL103` 的求解执行”，而不是先服务 `SOL200`。

## 7.1 目标

让 Python 服务可以稳定调用 Nastran 执行：

- 普通 `BDF`
- 生成后的 `SOL200 BDF`

## 7.2 建议落位

复用并扩展：

- `services/model_update/analysis/solver_service.py`

## 7.3 主要任务

### C1. 补一个通用 `run_nastran_bdf_job()`

当前已有 `run_nastran_sol103_job()`，但它偏向 `SOL103` 工作流。  
建议补一个更通用的“已有 BDF 直接运行”能力。

### C2. 补 `run_nastran_sol200_job()`

流程：

1. 调 `nastran_sol200.py` 生成输入
2. 拼接命令
3. 调 Nastran
4. 收集产物

### C3. 增强失败信息

建议返回：

- `.f06` 路径
- `.op2` 路径
- `stdout_tail`
- `stderr_tail`
- `artifacts`

### C4. 参考 BAS 补求解前后处理

第一阶段至少考虑：

- 输出目录准备
- 旧结果冲突检查
- `.f06` 是否存在
- 求解成功但没产出 `.op2` 时给出明确错误

## 7.4 验收标准

1. 能运行已有普通 `BDF`
2. 能运行生成后的 `SOL200 BDF`
3. 返回中能明确看到产物路径
4. 求解失败时，错误信息足够支持定位

## 7.5 风险点

- Nastran 命令参数与 FEMTools 脚本默认 flags 不一致
- 工作目录不对导致产物找不到
- 求解器返回码正常，但实际 `.f06` 里有 `FATAL`

## 8. 任务包 D：OP2 模态解析

> 顺序修正说明  
> 这一包在新的顺序里应先于 `SOL200` 生成和灵敏度矩阵解析完成。

这是第二条关键主线。

## 8.1 目标

从 `OP2` 里稳定提取：

- 模态阶次
- 模态频率
- 节点振型

并桥接到现有 `t_mt_py_fem_modal_result`。

## 8.2 建议落位

新增文件：

- `services/model_update/importers/op2_service.py`

## 8.3 主要任务

### D1. 建立基础 `OP2` 读取函数

支持：

- `op2_only`
- `bdf_plus_op2`

### D2. 建立模态提取函数

从：

- `op2.eigenvectors`

提取：

- `mode_no`
- `frequency`
- `u1/u2/u3`
- 可选 `ur1/ur2/ur3`

### D3. 建立节点 ID 映射逻辑

必须按节点 ID 对齐，不允许按结果数组顺序偷懒。

### D4. 组装成当前模态导入 payload

兼容：

- `import_fe_modal_results()`

### D5. 做一个模态预览输出

返回少量节点样本和频率摘要，便于人工检查。

## 8.4 验收标准

1. 能从真实模态 `OP2` 中取出 1 阶以上模态
2. 频率值和外部工具查看结果一致或近似一致
3. 振型节点数和模型节点规模相匹配
4. 导入 `t_mt_py_fem_modal_result` 后，现有模态相关性链路能读到数据

## 8.5 风险点

- `OP2` 不带完整几何
- 某些节点在结果里缺失
- 频率字段在不同样本里来源不同

## 9. 任务包 E：OP2 灵敏度矩阵解析

> 顺序修正说明  
> 这一包是第二条主线，不是第一条主线入口；它依赖前面的模态模型、模态结果和参数选择已经明确。

这是第一阶段技术风险最高的一包。

## 9.1 目标

从带 `SOL200` 灵敏度输出的 `OP2` 中提取：

- 原始灵敏度矩阵
- 行列标签
- 可映射的参数和响应名称

## 9.2 建议落位

继续放在：

- `services/model_update/importers/op2_service.py`

但实现上要和模态解析函数分开。

## 9.3 主要任务

### E1. 识别可用灵敏度结果块

这一部分必须基于真实样本确认。  
不能只凭想当然。

### E2. 提取原始二维矩阵

先不急着写库，先拿到：

- 矩阵维度
- 数值
- 原始标签

### E3. 输出 JSON 预览

这一阶段非常重要。  
要让人工能先看：

- 行数对不对
- 列数对不对
- 标签对不对
- 数值量级对不对

### E4. 建立业务映射

把：

- 原始列 -> 参数名
- 原始行 -> 响应名

映射成当前系统能用的定义。

### E5. 复用现有灵敏度写库结构

桥接到：

- `t_mt_py_fem_analysis_run`
- `t_mt_py_fem_response_def`
- `t_mt_py_fem_parameter_def`
- `t_mt_py_fem_sensitivity_result`

## 9.4 验收标准

1. 能对真实灵敏度 `OP2` 输出矩阵预览
2. 预览中行列数量和预期一致
3. 至少有一套样本能成功写入现有灵敏度表结构
4. 后续矩阵查询接口能读出写入结果

## 9.5 风险点

- 样本不足时，根本无法确认灵敏度块位置
- 原始标签不完整时，业务映射需要额外辅助信息
- 原始值和归一化值的语义可能混淆

### 特别说明

任务包 E 很可能是第一阶段唯一需要“拿到真实样本后再二次修正实现”的部分。  
这很正常，不是设计有问题，而是 `OP2` 灵敏度块本来就比模态块更依赖真实文件验证。

## 10. 任务包 F：接口与异步任务接线

> 顺序修正说明  
> 接口接线时也应先接：
> 1. `SOL103` 求解
> 2. `OP2` 模态预览/导入
> 3. 再接 `SOL200` 预览/生成/求解
> 4. 最后接 `OP2` 灵敏度预览/导入

这是把能力真正暴露出去的一包。

## 10.1 目标

让前端或外部调用方可以通过稳定接口使用：

- 预览
- 生成
- 求解
- 模态导入
- 灵敏度导入

## 10.2 建议落位

主要修改：

- `webapi/models.py`
- `webapi/routers/solver.py`
- 可选新增 Nastran 相关导入路由
- 复用 `webapi/background_jobs.py`

## 10.3 第一阶段优先接口

建议按顺序接：

### F1. 同步预览与生成

- `POST /solver/nastran/sol200/preview`
- `POST /solver/nastran/sol200/generate`

### F2. 求解执行

- `POST /solver/nastran/run`
- `POST /solver/nastran/sol200/run`

建议支持：

- `async_submit`

### F3. OP2 模态

- `POST /import/op2/modal/preview`
- `POST /import/op2/modal/store`

### F4. OP2 灵敏度

- `POST /import/op2/sensitivity/preview`
- `POST /import/op2/sensitivity/store`

## 10.4 异步状态接口

第一阶段建议不要为每个 Nastran 子能力单独发明一套状态结构。  
统一复用当前后台任务返回格式。

建议至少提供一条状态查询路由：

- `GET /solver/nastran/tasks?task_id=...`

或后续收敛成全局任务查询接口。

## 10.5 验收标准

1. 至少有 1 个求解接口支持异步提交
2. 任务状态能查到：
   - `submitted`
   - `running`
   - `succeeded/failed`
3. 运行中能看到阶段性 `progress`
4. 失败时能看到足够排障的 `error.details`

## 11. 推荐开发顺序

> 顺序修正说明  
> 推荐开发顺序现在应以“先 `SOL103`，后 `SOL200`”为准，不再以 `SOL200` 为第一入口。

真正动手时，建议按下面顺序做，不建议并行乱开。

### 顺序 1：任务包 B

先做 `SOL200` 生成器。

原因：

- 没有输入生成器，后面求解和解析都没法打通

### 顺序 2：任务包 C

再把求解器调用接好。

原因：

- 先确认“输入能跑”

### 顺序 3：任务包 D

再做 `OP2` 模态解析。

原因：

- 模态结果比灵敏度矩阵更稳，适合先打通结果读取层

### 顺序 4：任务包 F 的前半段

先接：

- preview
- generate
- run

原因：

- 让主链路尽快可以从接口触发

### 顺序 5：任务包 E

最后再碰灵敏度矩阵。

原因：

- 这是最依赖真实样本的部分

### 顺序 6：任务包 F 的后半段

最后接：

- OP2 模态导入接口
- OP2 灵敏度导入接口

## 12. 建议的阶段性里程碑

> 顺序修正说明  
> 里程碑顺序应理解为：  
> M1 `SOL103` 求解可用 -> M2 模态导入可用 -> M3 `SOL103 -> SOL200` 生成/求解可用 -> M4 灵敏度预览可用

为了让开发过程更容易管理，建议设 4 个里程碑。

## 里程碑 M1：输入生成可用

表示：

- 能从普通 `BDF` 生成 `SOL200 BDF`
- 可以人工检查输出

## 里程碑 M2：求解执行可用

表示：

- 能本地调起 Nastran 跑生成结果
- 能回收 `.f06/.op2`

## 里程碑 M3：模态导入可用

表示：

- 能从 `OP2` 读模态
- 能写入 `t_mt_py_fem_modal_result`
- 能接到现有模态相关性流程

## 里程碑 M4：灵敏度预览可用

表示：

- 能从 `OP2` 读到灵敏度矩阵预览
- 至少一套样本能写入现有灵敏度表结构

## 13. 第一阶段最需要警惕的风险

如果只挑最重要的 4 个风险，我会列这几个。

### 风险 1：没有真实灵敏度 `OP2` 样本

这会直接卡住任务包 E。

### 风险 2：参数目标映射规则不清楚

比如一个参数到底挂哪个 `PID` / `MID`，如果输入不明确，生成器会很难稳定。

### 风险 3：Nastran 实际运行参数与 BAS 默认行为有差异

这会导致：

- 能跑但输出不对
- 或者根本没生成预期结果文件

### 风险 4：模态结果节点对齐偷懒

如果没有按节点 ID 映射，后面所有：

- 模态比对
- DAC / DSF
- 将来 MAC

都会悄悄错掉，而且很难第一时间发现。

## 14. 这一阶段最推荐先写哪些测试

虽然你当前项目约定是不在这里跑测试，但测试代码还是值得先补。

第一阶段最值得优先写的测试是：

### T1. `SOL200` 生成器最小样本测试

校验：

- `DESVAR`
- `DVPREL1 / DVMREL1`
- `DRESP1`

### T2. `Nastran` 命令拼接测试

校验：

- `job_name`
- `output_dir`
- `extra_args`

### T3. 模态结果 payload 组装测试

校验：

- 节点映射
- 频率字段
- 输出结构是否兼容 `import_fe_modal_results`

### T4. 灵敏度矩阵桥接测试

校验：

- `response_names`
- `parameter_names`
- `matrix -> response_def / parameter_def / sensitivity_result`

## 15. 这份实施计划的结论

> 顺序修正说明  
> 第一阶段的主线应正式收敛为：  
> `SOL103 求解 -> OP2 模态 -> 模态导入/比对 -> SOL103 改写 SOL200 -> OP2 灵敏度 -> 接口异步化`

如果把第五份稿子浓缩成一句话，就是：

**第一阶段不要试图“一口吃掉 Nastran”，而是按“SOL200 生成 -> 求解执行 -> OP2 模态 -> OP2 灵敏度 -> 接口异步化”这条顺序逐步打通，并把灵敏度矩阵部分明确列为最依赖真实样本的高风险包。**

这样安排的好处是：

- 每一步都有独立验收点
- 哪一步卡住都能单独排查
- 前面 80% 的工作不会被最后 20% 的灵敏度细节绑死

这也是最适合当前仓库现状的一种推进方式。
