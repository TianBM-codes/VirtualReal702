# 模型修正接口清单

本文档根据当前代码重新整理，范围主要包含：

- `app.py`
- `webapi/routers/*.py`
- 与模型修正前后处理直接相关的 `src/l3/api/routes/*.py` 查询接口

补充说明：

- 早期版本中，`src/l3` 下的 ODB/L3 接口不在本文档范围内。
- 从当前版本开始，凡是已经被模型修正、灵敏度云图、Bayesian 更新前端直接依赖的 `src/l3` 查询接口，也纳入本文档统一维护。
- 目标是把“模型修正链路实际会调用到的接口”尽量收敛到同一份文档中，避免代码已变更但文档缺失。

## 1. 通用约定

### 1.1 成功返回包体

除个别服务函数本身返回 `null` 外，接口统一包裹为：

```json
{
  "ok": true,
  "code": 200,
  "message": "success message",
  "data": {}
}
```

### 1.2 失败返回包体

```json
{
  "ok": false,
  "code": 500,
  "message": "error message",
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "error message",
    "details": {}
  }
}
```

补充说明：

- 当前模型修正接口统一只返回两种业务码：
  - `200`：接口执行成功
  - `500`：接口执行失败，需要查看 `message` 与 `error.details`
- 部分原始异常如果本来属于 `400/404` 等类型，后端会统一折叠为 `500` 返回；原始状态码会放进 `error.details.original_status_code`。

### 1.3 求解器路径约定

- Abaqus 不通过单独接口配置。
- 后端会优先读取 `service_config.json` 中的配置。
- 如果请求体里显式传入 `abaqus`，则以请求值为准。

### 1.4 路径输入新约定

从本次版本开始，模型修正相关接口逐步支持“两种传法并存”：

- 绝对路径：继续兼容旧接口写法，例如 `input_inp: "D:/demo/model.inp"`
- 文件名 / 项目内相对路径：前端只传文件名，后端按 `project_id` 对应的 project workspace 自动拼路径

通俗说就是：

- 输入文件可以继续直接传绝对路径
- 也可以传 `xxx_name` 这类字段，只写文件名或项目目录内相对路径
- 如果同时传了“绝对路径字段”和“文件名字段”，优先使用绝对路径字段

当前统一规则：

- project workspace 根目录来自 `service_config.json` 的 `APP_DATA_ROOT`
- 输入文件名会按 `APP_DATA_ROOT/<project_id>/...` 去找
- 中间计算文件默认写到 `APP_DATA_ROOT/<project_id>/cal/...`
- 灵敏度相关默认目录：`cal/sensitivity`
- 贝叶斯模型修正默认目录：`cal/bayesian`
- 本地求解默认目录：
  - Abaqus 通用求解：`cal/solver/abaqus`
  - Abaqus 伴随：`cal/solver/abaqus_adjoint`
  - Nastran SOL103：`cal/solver/nastran_sol103`
  - Nastran SOL200：`cal/solver/nastran_sol200`
  - PBS 下载结果：`cal`

补充说明：

- `xxx_name` 字段既可以只写文件名，也可以写 project workspace / 默认输出目录下的相对路径
- 为了安全，后端会限制这些相对路径不能跳出当前项目目录

## 2. 系统接口

### `POST /init`

接口含义：初始化数据库表。

功能说明：调用 `ensure_tables_exist()`，在开发阶段按当前代码创建所需表结构。

影响数据库：

- `db.py` 中模型修正链路相关表：建表/补表，仅确保表结构存在，不写入具体业务数据。

请求参数：无。

请求示例：

```json
{}
```

返回 `data` 样式：

```json
null
```

### `POST /project/config`

接口含义：保存项目级模型修正配置。

功能说明：保存试验模型包络尺寸、FEM 模型包络尺寸、缩放系数和附加配置。节点匹配参数、自动平移/旋转估计等流程会复用这里的配置。

- `t_mt_py_project_config`：写，按项目保存 `test_model_dims`、`fem_model_dims`、`coefficients` 和 `extra_json`。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |

| `project_id` | `int` | 是 | 项目 ID |

| `coefficients` | `object` | 否 | 缩放或换算系数字典 |
| `extra_json` | `object` | 否 | 额外配置 |

请求示例：

```json
{

    "y": 300.0,
    "z": 180.0

    "z": 175.0
  },

    "length_scale": 1.0

    "note": "manual config"
  }
}
```

返回 `data` 示例：

### `GET /calc/tasks/{task_id}`

接口含义：按任务 ID 查询异步计算任务状态。

功能说明：查询模型修正链路中的后台任务记录。第一版仅覆盖通过 `submit_background_task(...)` 提交的异步任务。

任务状态说明：

- `submitted`：任务已创建，尚未开始执行。
- `running`：任务正在执行。
- `success`：任务执行成功。
- `failed`：任务执行失败。

补充说明：

- 第一版任务记录存储在 MySQL 表 `t_mt_py_background_task`。
- 服务重启后，未完成的 `internal` 任务会自动重试，执行次数超过 3 次会标记失败。
- 服务重启后，`external_solver` 任务不会自动重跑，而是直接标记失败，错误信息为服务在外部求解期间重启，需要人工重新提交。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `task_id` | `string` | 是 | 后台任务 ID |

返回 `data` 示例：

```json
{

  "task_type": "solver.pbs.abaqus.run",

  "task_kind": "external_solver",
  "project_id": "101",
  "status": "running",
  "execute_count": 1,
  "max_execute_count": 3,
  "submitted_at": "2026-05-28T02:31:05.123456+00:00",
  "started_at": "2026-05-28T02:31:06.223456+00:00",
  "finished_at": null,
  "request": {
    "project_id": 101
  },
  "progress": {
    "phase": "running"
  },
  "result": null,
  "error": null
}
```

## 3. 试验数据接口

### `POST /import/unv`

接口含义：导入试验 UNV 文件。

功能说明：解析试验节点、单元、模态或静力结果，并写入试验相关表；同时会把测点信息写入 `t_mt_measuring_point_info`。

影响数据库：

- `t_mt_py_test_node`、`t_mt_py_test_element`：写，保存试验节点和单元。
- `t_mt_py_test_modal_frequency`、`t_mt_py_test_modal_shape`、`t_mt_py_test_modal_shape_real`、`t_mt_py_test_modal_shape_imag`：写，保存模态频率与振型。
- `t_mt_py_test_static_result`：写，保存静力结果。
- `t_mt_measuring_point_info`：写，保存或刷新测点信息。
- `t_mt_work_condition_project`：写，更新项目试验数据状态。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file_path` | `string` | 是 | UNV 文件路径 |
| `project_id` | `int` | 否 | 项目 ID，代码层面允许为空，但业务上建议必传 |
| `file_id` | `int` | 否 | 文件 ID |
| `clear_before_insert` | `bool` | 否 | 是否先清空该项目已有试验数据，默认 `true` |

请求示例：

```json
{
  "file_path": "D:/demo/test.unv",
  "project_id": 101,
  "clear_before_insert": true
}
```

返回 `data` 示例：

```json
{
```

### `POST /test/unit/convert`

接口含义：校正试验模型单位，并同步更新显示缩放系数。

功能说明：

- 目前仅支持 `MKS` 和 `MMKS` 两种单位体系互转。
- 当 `MKS -> MMKS` 时：
  - 试验节点坐标和测点坐标乘以 `1000`
  - 动态显示位移缩放系数乘以 `1000`
  - 静力显示位移缩放系数乘以 `1000`
- 当 `MMKS -> MKS` 时：
  - 试验节点坐标和测点坐标除以 `1000`
  - 动态显示位移缩放系数除以 `1000`
  - 静力显示位移缩放系数除以 `1000`
- 当 `from_unit` 与 `to_unit` 相同时，不会额外缩放坐标，但仍会回写当前单位状态。

补充说明：

- 该接口不会批量修改试验模态结果表或 `t_mt_static_test_data` 中的原始结果值。
- 动态模态振型显示会在读取时乘 `dynamic_displacement_display_scale`。
- 静力测点变形显示会在读取时乘 `static_displacement_display_scale`。
- 模态匹配、MAC、频率一致性分析不依赖这两个显示缩放系数。

影响数据库：

- `t_mt_py_test_node`：写，更新 `x/y/z` 与 `origin_x/origin_y/origin_z`。
- `t_mt_measuring_point_info`：写，更新 `x_position/y_position/z_position` 与 `x_position_ori/y_position_ori/z_position_ori`。
- `t_mt_py_project_config`：写，更新：
  - `coefficients.dynamic_displacement_display_scale`
  - `coefficients.static_displacement_display_scale`
  - `extra_json.test_unit_system`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `from_unit` | `string` | 是 | 原单位体系，当前支持 `MKS`、`MMKS` |
| `to_unit` | `string` | 是 | 目标单位体系，当前支持 `MKS`、`MMKS` |

请求示例 1：米制转毫米制

```json
{
  "project_id": 101,
  "from_unit": "MKS",
  "to_unit": "MMKS"
}
```

请求示例 2：毫米制转米制

```json
{
  "project_id": 101,
  "from_unit": "MMKS",
  "to_unit": "MKS"
}
```

- `submitted`：任务已提交，等待线程池执行。
- `running`：正在执行 Bayesian 迭代，`data.progress.current_iteration` 表示当前跑到第几轮，`data.progress.total_iterations` 表示总轮数。
- `succeeded`：执行成功，`data.result` 是压缩后的 Bayesian 结果摘要。
- `failed`：执行失败，`data.error` 包含错误信息。
- `aborted`：服务重启后恢复任务状态时，原来未完成的任务会被标记为中断。

### `POST /optimization/bayesian/modal_frequency/run`

接口含义：执行基于模态频率的 Bayesian 模型修正。

功能说明：读取已经入库的频率灵敏度矩阵，结合 `POST /correlation/modal/match` 等价的最终模态匹配结果，把“匹配后的 FEM 频率”当作当前模型响应，把“匹配后的试验频率”当作目标响应，然后执行贝叶斯参数更新。参数当前主要面向 `E`、`RHO` 这类 BDF / SOL200 频率修正参数。  
如果请求里传了 `input_bdf` / `input_bdf_name`，后端还会把更新后的参数值写回一个新的 BDF 文件，保存到项目 `cal/bayesian/modal_frequency` 目录下。  
这一版不会自动重新调用求解器，而是基于当前灵敏度矩阵做线性预测，所以它更像“先把频率修正链路打通并入库”，后面如果你还要接自动重算，可以在这条链上继续扩展。

- 程序会读取已导入的试验模态振型，对每个测点的 `UX/UY/UZ` 三个方向分别统计“全部已导入模态中的最大绝对测量值”。
- 如果某个方向的最大绝对值小于 `min_match_score`，则认为该方向数据不可用，不写入 `t_mt_py_fem_dof_match`。
- 后续 `MAC` 计算只会使用已经通过该阈值筛选的 DOF 匹配对。
- `dof_matches_preview[*].match_score` 与 `rejected_dof_preview[*].match_score` 现在表示该方向的“最大绝对测量值”，不再表示三方向相对占比。

### `POST /optimization/modal_mac/sensitivity/compute`

- 这是一个“矩阵直算”接口。
- 它不依赖数据库里的响应目录，也不要求先生成 `SOL200`。
- 你只要把试验振型 `phi_exp`、仿真振型 `phi_sim`、振型灵敏度 `dphi_dp` 和模态配对关系 `pairs` 传进来，就能直接得到：
  - `MAC`
  - 符号对齐结果
  - `dMAC/dp`
- 这个接口主要是给两类场景准备的：
  - 用 `FEMTools` 的振型、灵敏度矩阵直接对比公式是否一致
  - 在后续正式接 `SOL200 -> dPhi/dp -> dMAC/dp` 全链之前，先单独验证 MAC 灵敏度数学路径

输出口径说明：

- 接口默认使用百分号口径，`mac_scale=100.0`
- 也就是说返回里的：
  - `mac_matrix`
  - `pair_results[].mac`
  - `pair_results[].dmac_dp`
  都已经自动乘了 `100`
- 同时也会保留原始 `0~1` 口径：
  - `mac_matrix_raw`
  - `pair_results[].mac_raw`
  - `pair_results[].dmac_dp_raw`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `phi_exp` | `array \| object` | 是 | 试验振型矩阵，形状 `N_sensor x N_mode_exp`；可直接传二维数组，也可传 `{path: ...}` |
| `phi_sim` | `array \| object` | 是 | 仿真振型矩阵，形状 `N_sensor x N_mode_sim` |
| `dphi_dp` | `array \| object` | 是 | 仿真振型对参数的灵敏度，形状 `N_mode_sim x N_sensor x N_param` |
| `pairs` | `array` | 是 | 模态配对列表 |
| `pairs[].exp_mode` | `int` | 是 | 试验模态序号 |
| `pairs[].sim_mode` | `int` | 是 | 仿真模态序号 |
| `index_base` | `int` | 否 | 序号基准，支持 `0` 或 `1`，默认 `1` |
| `parameter_names` | `string[]` | 否 | 参数名列表 |
| `sensor_labels` | `string[]` | 否 | 传感器/测点标签列表 |
| `mac_scale` | `float` | 否 | 输出缩放系数，默认 `100.0` |

请求示例 1：直接传矩阵

```json
{
  "phi_exp": [
    [1.0, 0.1],
    [0.5, 0.3],
    [0.2, 0.8]
  ],
  "phi_sim": [
    [0.9, 0.2],
    [0.45, 0.35],
    [0.25, 0.75]
  ],
  "dphi_dp": [
    [
      [0.01, 0.02],
      [0.03, 0.01],
      [0.02, -0.01]
    ],
    [
      [0.00, 0.03],
      [0.01, 0.02],
      [0.02, 0.01]
    ]
  ],
  "pairs": [
    {
      "exp_mode": 1,
      "sim_mode": 1
    },
    {
      "exp_mode": 2,
      "sim_mode": 2
    }
  ],
  "parameter_names": ["E1", "E2"],
  "sensor_labels": ["N101_U3", "N102_U3", "N103_U3"],
  "index_base": 1,
  "mac_scale": 100.0
}
```

请求示例 2：传文件路径

```json
{
  "phi_exp": {
    "path": "D:/demo/phi_exp.csv",
    "delimiter": ","
  },
  "phi_sim": {
    "path": "D:/demo/phi_sim.csv",
    "delimiter": ","
  },
  "dphi_dp": {
    "path": "D:/demo/dphi_dp.npy"
  },
  "pairs": [
    {
      "exp_mode": 1,
      "sim_mode": 1
    }
  ],
  "mac_scale": 100.0
}
```

返回重点字段：

- `mac_matrix`：百分号口径的 MAC 矩阵
- `mac_matrix_raw`：原始 `0~1` 口径 MAC 矩阵
- `pair_results[].mac`：当前模态对的百分号口径 MAC
- `pair_results[].dmac_dp`：当前模态对的百分号口径灵敏度
- `pair_results[].g_vector`：公式里的 `g_ij`
- `sign_flips`：为了和试验振型方向一致，哪些仿真模态被乘了 `-1`

### `POST /solver/nastran/sol200/run_and_store`

接口含义：生成并运行 `SOL200`，然后把本次求解输出的灵敏度结果自动解析入库。

功能说明：

- 这条接口是 `POST /solver/nastran/sol200/run` 和 `POST /import/op2/sensitivity/store` 的一体化封装。
- 前半段：
  - 读取当前请求或数据库中的 `SOL200` 参数/响应配置
  - 生成 `SOL200` BDF
  - 调用本地 Nastran 执行求解
- 后半段：
  - 自动从本次求解输出里定位 `op2`
  - 如果没有 `op2`，则继续回退查找 `sens.csv / sol200_sens.csv / UNIT11` 这类矩阵结果文件
  - 自动复用本次生成的 `metadata_json`
  - 自动以本次 `output_bdf` 作为几何基准文件
  - 调用灵敏度导入逻辑，把矩阵写入数据库
- 这样前端不需要再手工发第二次“导入 OP2 灵敏度”请求。

适用场景：

- 你希望后端一口气完成：
  - `SOL200` 求解
  - `OP2` 灵敏度解析
  - 灵敏度矩阵入库
- 而不是先调 `/solver/nastran/sol200/run`，再自己补调 `/import/op2/sensitivity/store`

影响数据库：

- `t_mt_py_fem_selected_parameter`：可能读，当请求里没有直接传 `parameters` 且项目已配置正式参数目录时，`SOL200` 配置解析链会读取。
- `t_mt_py_fem_dynamic_response_catalog`：可能读，当请求里没有直接传 `responses` 且项目已配置正式响应目录时，`SOL200` 配置解析链会读取。
- `t_mt_py_fem_sol200_parameter_config`、`t_mt_py_fem_sol200_response_config`：可能读，当本次 `SOL200` 走数据库配置源时会读取。
- `t_mt_py_fem_analysis_run`：写，保存本次灵敏度批次主记录。
- `t_mt_py_fem_sensitivity_matrix_response`：写，保存灵敏度矩阵响应行定义。
- `t_mt_py_fem_sensitivity_matrix_parameter`：写，保存灵敏度矩阵参数列定义。
- `t_mt_py_fem_sensitivity_matrix_result`：写，保存灵敏度矩阵明细。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `batch_no` | `string` | 否 | 灵敏度批次号，默认 `"1"` |
| `case_name` | `string` | 否 | 本次案例名，默认 `"nastran_sol200"` |
| `input_bdf` | `string` | 否 | 输入 BDF 绝对路径；与 `input_bdf_name` 二选一，优先级更高 |
| `input_bdf_name` | `string` | 否 | 输入 BDF 文件名或项目内相对路径 |
| `output_bdf` | `string` | 否 | 输出 BDF 绝对路径 |
| `output_bdf_name` | `string` | 否 | 输出 BDF 文件名或项目内相对路径 |
| `parameters` | `array` | 否 | 显式传入的 `SOL200` 参数列表；不传时走数据库配置源 |
| `parameter_preset` | `object` | 否 | 参数便捷预设，例如 `all_used_material_e_rho`、`all_elements_e` |
| `responses` | `array` | 否 | 显式传入的 `SOL200` 响应列表；不传时走数据库配置源 |
| `settings` | `object` | 否 | `SOL200` 生成/求解设置 |
| `nastran` | `string` | 否 | Nastran 可执行路径 |
| `run_solver` | `bool` | 否 | 是否实际执行求解，默认 `true` |
| `timeout_sec` | `int` | 否 | 求解超时时间，单位秒 |
| `extra_args` | `string[]` | 否 | 额外命令行参数 |
| `parameter_names` | `string[]` | 否 | 只入库指定参数列；不传默认全部 |

| `cloud_field_name` | `string` | 否 | 云图 field 名，默认 `SENSITIVITY_CLOUD` |
| `async_submit` | `bool` | 否 | 是否后台异步提交，默认 `false` |

补充说明：

- 这条接口优先使用 `op2` 作为灵敏度结果源。
- 如果本次 `SOL200` 没有产出 `op2`，但产出了：
  - `sens.csv`
  - `sol200_sens.csv`
  - `UNIT11` 这类矩阵文件
  接口也会继续完成入库。
- 当 `write_cloud_result=true` 时，后半段不只会把矩阵写入 MySQL，还会继续把结果翻译成 external-field 形式写入项目 workspace 的 HDF5 结果目录，供 `/api/odb/{odb_id}/...` 查询接口直接读取。
- 这条接口默认 `write_cloud_result=true`，因此当前前端通常可以直接把它产出的 `result_group + step + field` 当作云图读取入口。
- 只有当 `op2` 和可识别的矩阵结果文件都没有找到时，接口才会报错。
- `metadata_json` 会优先复用本次 `SOL200` 生成阶段产出的 sidecar 文件，因此前端通常不需要再单独传它。
- 如果你只是想先生成或先运行，不立刻入库，仍然可以继续使用：
  - `POST /solver/nastran/sol200/generate`
  - `POST /solver/nastran/sol200/run`
- 如果你已经手工运行完 Nastran，只想补做入库，仍然可以继续使用：
  - `POST /import/op2/sensitivity/store`

### `POST /solver/nastran/sol200/sync_generate_run_and_store`

### `POST /import/op2/sensitivity/store_cloud`

接口含义：导入 Nastran `OP2` / 灵敏度矩阵后，不只把矩阵入库，还会把结果再写进项目 workspace 的 HDF5 结果目录，让前端可以像 Abaqus 灵敏度云图一样直接读取。

功能说明：

- 前半段复用 `POST /import/op2/sensitivity/store` 的逻辑：
  - 解析 `op2_path` 或 `matrix_path`
  - 结合 `bdf_path` / `metadata_json` / 数据库里已保存的批次元数据，整理响应行和参数列
  - 把灵敏度矩阵写入 MySQL
- 后半段新增一层“可视化回灌”：
  - 根据参数元数据里的 `element_id / property_id / material_id`，反查这个参数实际影响哪些单元
  - 组装成项目内部统一的 external-field 结果结构
  - 写入项目 workspace 下新的 HDF5 结果文件，并登记到 `manifest.db`
- 写完以后，L3 / 前端就会把它当成一个新的 `result_group` 来看，和 Abaqus 灵敏度云图走的是同一套读取链路。

为什么要单独做这个接口：

- `POST /import/op2/sensitivity/store` 只解决“矩阵入库”，适合后端计算和后续模型修正。
- 但前端云图需要的是“单元场结果”，不是一张二维矩阵。
- 所以这里单独补一个上层接口，专门负责把“矩阵语义”翻译成“单元云图语义”，底层仍然复用现有 H5 写入能力，不重复造轮子。

影响文件：

- 项目 workspace：写
  - `l1/results/<cloud_result_group>/external__<cloud_step_name>__<cloud_field_name>.h5`
- 项目 workspace 的 `manifest.db`：写
  - `result_group_meta`
  - `steps`
  - `frames`
  - `result_files`
  - `result_blocks`
- MySQL：写
  - 与 `POST /import/op2/sensitivity/store` 一样，仍会写灵敏度矩阵主表和明细表

### `GET /api/odb/{odb_id}/results/frame-scalar-range`

接口含义：按多个 `instance` 计算某个结果字段当前帧的全局数值范围。

功能说明：

- 用于前端在多实例同时上色前，先拿到统一的颜色归一化区间。
- 该接口会针对每个 `instance` 逐个调用结果读取服务，返回：
  - `instance_ranges`
  - `global_min`
  - `global_max`
- 当前版本已兼容以下几类“前端参数不完全精确”的情况：
  - `step` 传 `Bayesian-Update`，后端可自动解析到真实 step `BayesianUpdate`
  - `field` 传 `SENSITIVITY_CLOUD__FRAME_0000`，后端可自动回退到底层源字段 `SENSITIVITY_CLOUD`
  - `result_group` 不传或传多个时，后端会按 `result_files` 自动尝试匹配

影响数据库 / 文件：

- 项目 workspace 下 `manifest.db`
  - `result_files`：读
- 项目 workspace 下 HDF5 结果文件：读
- 不写数据库和文件。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `odb_id` | `string` | 是 | 已加载到 L3 registry 中的 ODB / project ID |
| `instances` | `string` | 是 | 逗号分隔的实例名列表，例如 `PART-1-1,PART-2-1` |
| `step` | `string` | 是 | step 名 |
| `field` | `string` | 是 | field 名；也支持 `__FRAME_0000` 这种帧别名 |
| `frame` | `int` | 否 | 帧下标，默认 `0` |
| `component_idx` | `int` | 否 | 分量下标；不传时默认按模长或标量处理 |
| `mode` | `string` | 否 | `smooth` 或 `flat`，默认 `smooth` |
| `result_group` | `string[]` | 否 | 可重复传多个结果组名，后端按顺序尝试 |
| `feature_angle` | `float` | 否 | 几何分区角度阈值，默认 `20.0` |
| `average_threshold` | `float` | 否 | 条件平均阈值，默认 `0.75` |
| `use_geometry_split` | `bool` | 否 | 是否启用几何分区，默认 `true` |

请求示例：

```text
GET /api/odb/254/results/frame-scalar-range?instances=PART-1-1&step=Bayesian-Update&field=PARAMETER_RELATIVE_DELTA_PERCENT&result_group=bayesian_sol200
```

返回 `data` 示例：

```json
{
  "global_min": -12.5,
  "global_max": 8.2,
  "instance_ranges": {
    "PART-1-1": [-12.5, 8.2]
  }
}
```

补充说明：

- 这个接口只返回范围，不返回顶点数组或颜色数组。
- 一般前端会先调它，再调用 `/api/odb/{odb_id}/results/frame-scalars`，把返回的 `global_min / global_max` 作为统一归一化范围传入。
