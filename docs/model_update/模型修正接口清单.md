# 模型修正接口清单

本文档根据当前代码重新整理，范围仅包含 `src` 之外的接口，也就是：

- `app.py`
- `webapi/routers/*.py`

`src/l3` 下的 ODB/L3 接口不在本文档范围内。

## 1. 通用约定

### 1.1 成功返回包体

除个别服务函数本身返回 `null` 外，接口统一包裹为：

```json
{
  "ok": true,
  "code": 200,
  "message": "success message",
  "data": {}
}
```

### 1.2 失败返回包体

```json
{
  "ok": false,
  "code": 400,
  "message": "error message",
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "error message",
    "details": {}
  }
}
```

### 1.3 求解器路径约定

- Abaqus 不通过单独接口配置。
- 后端会优先读取 `service_config.json` 中的配置。
- 如果请求体里显式传入 `abaqus`，则以请求值为准。

## 2. 系统接口

### `POST /init`

接口含义：初始化数据库表。

功能说明：调用 `ensure_tables_exist()`，在开发阶段按当前代码创建所需表结构。

影响数据库：

- `db.py` 中模型修正链路相关表：建表/补表，仅确保表结构存在，不写入具体业务数据。

请求参数：无。

请求示例：

```json
{}
```

返回 `data` 样式：

```json
null
```

## 3. 试验数据接口

### `POST /import/unv`

接口含义：导入试验 UNV 文件。

功能说明：解析试验节点、单元、模态或静力结果，并写入试验相关表；同时会把测点信息写入 `t_mt_measuring_point_info`。

影响数据库：

- `t_mt_py_test_node`、`t_mt_py_test_element`：写，保存试验节点和单元。
- `t_mt_py_test_modal_frequency`、`t_mt_py_test_modal_shape`、`t_mt_py_test_modal_shape_real`、`t_mt_py_test_modal_shape_imag`：写，保存模态频率与振型。
- `t_mt_py_test_static_result`：写，保存静力结果。
- `t_mt_measuring_point_info`：写，保存或刷新测点信息。
- `t_mt_work_condition_project`：写，更新项目试验数据状态。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file_path` | `string` | 是 | UNV 文件路径 |
| `project_id` | `int` | 否 | 项目 ID，代码层面允许为空，但业务上建议必传 |
| `file_id` | `int` | 否 | 文件 ID |
| `clear_before_insert` | `bool` | 否 | 是否先清空该项目已有试验数据，默认 `true` |

请求示例：

```json
{
  "file_path": "D:/demo/test.unv",
  "project_id": 101,
  "clear_before_insert": true
}
```

返回 `data` 示例：

```json
{
  "file_path": "D:/demo/test.unv",
  "result_kind": "modal",
  "cleared_before_insert": true,
  "test_node_count": 120,
  "measuring_point_count": 120,
  "test_element_count": 80,
  "test_mode_count": 6,
  "test_static_result_count": 0
}
```

| 参数名 | 类型 | 必填 | 说明 |

| `static_result_id` | `int` | 否 | 静力结果主键 ID；传入时优先按此定位 |
| `load_case_no` | `int` | 否 | 载荷工况号 |
| `result_no` | `int` | 否 | 结果号 |

请求示例：

```json
{
  "project_id": 101,
  "load_case_no": 1,
  "result_no": 1,
  "scale": 10.0
}
```

返回 `data` 示例：

```json
[
  {
    "sensor_label": "WY1",
    "sensor_type": "位移",
    "sensor_pos": [0.01, 0.0, 0.0]
  }
]
```

- `t_mt_py_fem_node_octree_cache`：写，保存节点八叉树缓存元数据。

### `POST /optimization/parameter/create`

接口含义：创建优化参数。

功能说明：从已导入的 INP 参数能力目录中，按“优化参数类型 + 对应集合名称”生成正式参与优化的参数记录；`selection_mode` 未传时由后端根据集合能力自动推断。

补充说明：

- 当前最小必填输入为：`project_id`、优化参数类型、`set_name`。
- 优化参数类型当前建议直接传 `quantity_code`；`candidate_code` 仅作为兼容别名保留。
- `set_name` 支持单个字符串或字符串数组。
- 传多个 `set_name` 时，会按每个集合分别创建参数。

影响数据库：

- `t_mt_py_fem_quantity_set_capability`：读，校验目标集合是否支持当前修正量及选择模式。
- `t_mt_py_fem_selected_parameter`：读写，检查目标集合是否与现有参数重叠，并写入最终优化参数记录。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `set_name` | `string \| string[]` | 是 | 目标集合名，支持单个或多个 |
| `quantity_code` | `string` | 是 | 优化参数类型/修正量编码，目前主要为 `E`、`H` |
| `lower` | `float` | 是 | 参数下界 |
| `upper` | `float` | 是 | 参数上界 |
| `candidate_code` | `string` | 否 | 候选参数编码，兼容旧调用方式 |
| `prob_id` | `int` | 否 | 问题 ID，默认 `0` |
| `selection_mode` | `string` | 否 | 选择模式；未传时通常会自动解析为 `GLOBAL` 或 `LOCAL` |
| `parameter_name` | `string` | 否 | 自定义参数名 |
| `scatter` | `float` | 否 | 参数散度 |
| `description` | `string` | 否 | 备注说明，默认空字符串 |
| `set_type` | `string` | 否 | 集合类型，如 `ELSET` |
| `set_scope` | `string` | 否 | 集合范围，如 `PART`、`ASSEMBLY` |
| `instance_name` | `string` | 否 | 实例名 |
| `part_name` | `string` | 否 | 零件名 |

请求示例：

```json
{
  "project_id": 101,
  "set_name": "SET_A",
  "quantity_code": "E",
  "lower": 100000.0,
  "upper": 300000.0,
  "prob_id": 0,
  "parameter_name": "E@SET_A"
}
```

接口含义：执行贝叶斯模型修正。

## 7. 灵敏度接口

### `POST /sensitivity/run_and_store`

接口含义：直接运行已有的灵敏度分析 INP，并将解析后的灵敏度矩阵存库。

功能说明：调用方传入已经准备好的灵敏度 `inp` 文件，服务端执行 Abaqus 求解，生成 `odb` 后构建 workspace，提取归一化灵敏度矩阵并保存到数据库。求解成功且 workspace 构建完成后，会删除常见 Abaqus 过程文件，只保留 `odb`、`inp` 与 workspace。

影响数据库：

- `t_mt_py_fem_analysis_run`：写，创建或更新当前批次灵敏度运行记录。
- `t_mt_py_fem_response_def`、`t_mt_py_fem_parameter_def`、`t_mt_py_fem_sensitivity_result`：写，保存灵敏度矩阵的响应定义、参数定义和矩阵值。
- `t_mt_py_fem_selected_parameter`：写，清空旧记录并按当前 `inp` 临时重建本次运行使用的参数映射。
- 外部结果服务：可选调用 `/api/odb/{odb_id}/results/external-field`，将灵敏度结果映射回单元/节点后写入 ODB 外部结果。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `input_inp` | `string` | 是 | 已准备好的灵敏度分析 INP 路径 |
| `output_dir` | `string` | 是 | 计算输出目录 |
| `step` | `string` | 是 | 结果步名，不再自动猜测 |
| `instances` | `string[]` | 是 | 参与提取的实例列表，不再自动猜测 |
| `field_prefix` | `string` | 是 | 灵敏度字段前缀，例如 `d_U_` |
| `response_component` | `string` | 是 | 响应分量，例如 `U1`、`U2` |
| `position` | `string` | 是 | 结果位置，例如 `NODAL`、`ELEMENT_NODAL` |
| `batch_no` | `string` | 否 | 批次号，默认 `"1"` |
| `aggregation` | `string` | 否 | 聚合方式，默认 `max_abs` |
| `frame` | `int` | 否 | 帧号，默认 `0` |
| `abaqus` | `string` | 否 | Abaqus 命令 |
| `python3` | `string` | 否 | Python 解释器 |

## 9. DOF 匹配、响应目录、结果导入与相关性接口

### `POST /match/dofs`

接口含义：试验自由度与 FEM 自由度匹配。

功能说明：基于已完成的节点匹配关系，为每个试验点生成 `UX/UY/UZ` 到 FEM 自由度的映射，并写入 `t_mt_py_fem_dof_match`。在 `modal_unv` 模式下，会先根据试验模态数据计算每个平动方向的 `match_score`，低于阈值的 DOF 不写入匹配表。

影响数据库：

- `t_mt_py_test_modal_shape_real`、`t_mt_py_test_modal_shape_imag`：读，分析试验模态方向信息。
- `t_mt_py_fem_node_match`：读，读取节点匹配结果。
- `t_mt_py_fem_dof_match`：写，保存试验 DOF 到 FEM DOF 的映射。
- `t_mt_py_fem_response_catalog`、`t_mt_py_fem_modal_correlation`：写，`overwrite=true` 时清理依赖旧 DOF 匹配的下游结果。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `overwrite` | `bool` | 否 | 是否覆盖旧结果，默认 `true` |
| `min_match_score` | `float` | 否 | DOF 匹配分数阈值；仅 `modal_unv` 模式使用，不传时默认 `1e-8` |

请求示例：

```json
{
  "project_id": 101,
  "overwrite": true,
  "min_match_score": 0.05
}
```

返回 `data` 示例：

```json
{
  "project_id": 101,
  "node_match_count": 30,
  "dof_match_count": 74,
  "rejected_dof_count": 16,
  "min_match_score": 0.05,
  "dof_matches_preview": [
    {
      "test_node_id": "1",
      "test_dof": "UX",
      "instance_name": "PART-1-1",
      "part_name": "PART-1",
      "fem_node_label": 1001,
      "fem_dof": "U1",
      "direction": [1.0, 0.0, 0.0],
      "match_score": 1.0,
      "transform": {}
    }
  ],
  "rejected_dof_preview": [
    {
      "test_node_id": "8",
      "test_dof": "UZ",
      "match_score": 0.012
    }
  ]
}
```

补充说明（2026-05-10）：

- `modal_unv` 模式下，`min_match_score` 的实际含义已经调整为“试验测量值阈值”。
- 程序会读取已导入的试验模态振型，对每个测点的 `UX/UY/UZ` 三个方向分别统计“全部已导入模态中的最大绝对测量值”。
- 如果某个方向的最大绝对值小于 `min_match_score`，则认为该方向数据不可用，不写入 `t_mt_py_fem_dof_match`。
- 后续 `MAC` 计算只会使用已经通过该阈值筛选的 DOF 匹配对。
- `dof_matches_preview[*].match_score` 与 `rejected_dof_preview[*].match_score` 现在表示该方向的“最大绝对测量值”，不再表示三方向相对占比。

## Nastran SOL200 / 灵敏度接口补充说明（2026-05-11）

- `POST /solver/nastran/sol200/preview`
- `POST /solver/nastran/sol200/generate`
- `POST /solver/nastran/sol200/run`

补充说明：

- `SOL200` 现在默认按 BAS 逻辑使用质量归一化特征向量，也就是 `dynamic.norm=MASS`。
- 如果显式传入的 `dynamic.norm` 不是 `MASS/2`，接口会直接报错，避免生成一份能运行但灵敏度语义不对的 deck。
- `SOL200` 现在默认使用更贴近 BAS 的 `PARAM POST=-5`，优先为灵敏度后处理保留结果文件。

- `POST /import/op2/sensitivity/preview`
- `POST /import/op2/sensitivity/store`

补充说明：

- 这两个接口除了原来的 `op2_path`，现在还支持可选参数 `matrix_path`。
- 当 `matrix_path` 传入时，接口会优先使用该结果文件提取灵敏度矩阵；如果 `matrix_path` 本身就是 `.op2`，则仍按 OP2 处理。
- 这让接口可以兼容 BAS/FEMTools 风格的矩阵结果文件，不再只能盯着 `op2`。
- 当前 `matrix_path` 的非 OP2 解析是“纯数字文本矩阵”的第一版启发式解析，因此返回里会带 source/source_kind/warnings，方便核对到底用了哪个文件、按什么方式读的。

请求示例补充：

```json
{
  "project_id": 1002,
  "batch_no": "1",
  "case_name": "nastran_sol200_case_01",
  "matrix_path": "D:/WorkSpace/Temp/Nastran/UNIT11",
  "bdf_path": "D:/WorkSpace/Temp/Nastran/227.bdf",
  "metadata_json": "D:/WorkSpace/Temp/Nastran/227_sol200.bdf.sol200.json"
```
