# 模型修正接口清单

本文档根据当前代码重新整理，范围仅包含 `src` 之外的接口，也就是：

- `app.py`
- `webapi/routers/*.py`

`src/l3` 下的 ODB/L3 接口不在本文档范围内。

## 1. 通用约定

### 1.1 成功返回包体

除个别服务函数本身返回 `null` 外，接口统一包裹为：

```json
{
  "ok": true,
  "code": 200,
  "message": "success message",
  "data": {}
}
```

### 1.2 失败返回包体

```json
{
  "ok": false,
  "code": 500,
  "message": "error message",
  "data": null,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "error message",
    "details": {}
  }
}
```

补充说明：

- 当前模型修正接口统一只返回两种业务码：
  - `200`：接口执行成功
  - `500`：接口执行失败，需要查看 `message` 与 `error.details`
- 部分原始异常如果本来属于 `400/404` 等类型，后端会统一折叠为 `500` 返回；原始状态码会放进 `error.details.original_status_code`。

### 1.3 求解器路径约定

- Abaqus 不通过单独接口配置。
- 后端会优先读取 `service_config.json` 中的配置。
- 如果请求体里显式传入 `abaqus`，则以请求值为准。

## 2. 系统接口

### `POST /init`

接口含义：初始化数据库表。

功能说明：调用 `ensure_tables_exist()`，在开发阶段按当前代码创建所需表结构。

影响数据库：

- `db.py` 中模型修正链路相关表：建表/补表，仅确保表结构存在，不写入具体业务数据。

请求参数：无。

请求示例：

```json
{}
```

返回 `data` 样式：

```json
null
```

### `POST /project/config`

接口含义：保存项目级模型修正配置。

功能说明：保存试验模型包络尺寸、FEM 模型包络尺寸、缩放系数和附加配置。节点匹配参数、自动平移/旋转估计等流程会复用这里的配置。

影响数据库：

- `t_mt_py_project_config`：写，按项目保存 `test_model_dims`、`fem_model_dims`、`coefficients` 和 `extra_json`。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `test_model_dims` | `object` | 否 | 试验模型包络尺寸，包含 `x/y/z` |
| `fem_model_dims` | `object` | 否 | FEM 模型包络尺寸，包含 `x/y/z` |
| `coefficients` | `object` | 否 | 缩放或换算系数字典 |
| `extra_json` | `object` | 否 | 额外配置 |

请求示例：

```json
{
  "project_id": 101,
  "test_model_dims": {
    "x": 1200.0,
    "y": 300.0,
    "z": 180.0
  },
  "fem_model_dims": {
    "x": 1180.0,
    "y": 305.0,
    "z": 175.0
  },
  "coefficients": {
    "length_scale": 1.0
  },
  "extra_json": {
    "note": "manual config"
  }
}
```

返回 `data` 示例：

```json
{
  "project_id": 101,
  "test_model_dims": {
    "x": 1200.0,
    "y": 300.0,
    "z": 180.0
  },
  "fem_model_dims": {
    "x": 1180.0,
    "y": 305.0,
    "z": 175.0
  },
  "coefficients": {
    "length_scale": 1.0
  },
  "extra_json": {
    "note": "manual config"
  }
}
```

## 3. 试验数据接口

### `POST /import/unv`

接口含义：导入试验 UNV 文件。

功能说明：解析试验节点、单元、模态或静力结果，并写入试验相关表；同时会把测点信息写入 `t_mt_measuring_point_info`。

影响数据库：

- `t_mt_py_test_node`、`t_mt_py_test_element`：写，保存试验节点和单元。
- `t_mt_py_test_modal_frequency`、`t_mt_py_test_modal_shape`、`t_mt_py_test_modal_shape_real`、`t_mt_py_test_modal_shape_imag`：写，保存模态频率与振型。
- `t_mt_py_test_static_result`：写，保存静力结果。
- `t_mt_measuring_point_info`：写，保存或刷新测点信息。
- `t_mt_work_condition_project`：写，更新项目试验数据状态。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file_path` | `string` | 是 | UNV 文件路径 |
| `project_id` | `int` | 否 | 项目 ID，代码层面允许为空，但业务上建议必传 |
| `file_id` | `int` | 否 | 文件 ID |
| `clear_before_insert` | `bool` | 否 | 是否先清空该项目已有试验数据，默认 `true` |

请求示例：

```json
{
  "file_path": "D:/demo/test.unv",
  "project_id": 101,
  "clear_before_insert": true
}
```

返回 `data` 示例：

```json
{
  "file_path": "D:/demo/test.unv",
  "result_kind": "modal",
  "cleared_before_insert": true,
  "test_node_count": 120,
  "measuring_point_count": 120,
  "test_element_count": 80,
  "test_mode_count": 6,
  "test_static_result_count": 0
}
```

## 9. DOF 匹配、响应目录、结果导入与相关性接口

### `POST /match/dofs`

接口含义：试验自由度与 FEM 自由度匹配。

功能说明：基于已完成的节点匹配关系，为每个试验点生成 `UX/UY/UZ` 到 FEM 自由度的映射，并写入 `t_mt_py_fem_dof_match`。在 `modal_unv` 模式下，会先根据试验模态数据计算每个平动方向的 `match_score`，低于阈值的 DOF 不写入匹配表。

影响数据库：

- `t_mt_py_test_modal_shape_real`、`t_mt_py_test_modal_shape_imag`：读，分析试验模态方向信息。
- `t_mt_py_fem_node_match`：读，读取节点匹配结果。
- `t_mt_py_fem_dof_match`：写，保存试验 DOF 到 FEM DOF 的映射。
- `t_mt_py_fem_response_catalog`、`t_mt_py_fem_modal_correlation`：写，`overwrite=true` 时清理依赖旧 DOF 匹配的下游结果。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |

| `min_match_score` | `float` | 否 | DOF 匹配分数阈值；仅 `modal_unv` 模式使用，不传时默认 `1e-8` |

补充说明（2026-05-10）：

- `modal_unv` 模式下，`min_match_score` 的实际含义已经调整为“试验测量值阈值”。
- 程序会读取已导入的试验模态振型，对每个测点的 `UX/UY/UZ` 三个方向分别统计“全部已导入模态中的最大绝对测量值”。
- 如果某个方向的最大绝对值小于 `min_match_score`，则认为该方向数据不可用，不写入 `t_mt_py_fem_dof_match`。
- 后续 `MAC` 计算只会使用已经通过该阈值筛选的 DOF 匹配对。
- `dof_matches_preview[*].match_score` 与 `rejected_dof_preview[*].match_score` 现在表示该方向的“最大绝对测量值”，不再表示三方向相对占比。

  - 展开远程 stage 目录
  - 创建远程任务目录
  - 上传主输入文件
  - 校验远程文件是否存在
  - 按应用类型组装提交参数
  - 提交任务
  - 可选轮询任务状态
  - 可选列出并下载结果文件
- 配置来源拆分为两部分：
  - `service_config.json` 中的 `PBS.env`、`PBS.environments` 与显式 `PBS.api_paths`
  - 工程配置 `project_config.pbs`
- 其中：
  - `service_config.json` 只负责 PBS 环境地址、账号、stage 路径模板以及各个接口路径；接口路径要直接完整列出，不再通过 `service_prefix/storage_prefix/auth_path` 之类字段拼装
- `project_config.pbs` 负责应用平台信息，例如 `ApplicationId`、`ApplicationName`、`VERSION`、`PLATFORM`，以及按需覆盖 `CORES/HOSTS/PRECISION`

影响数据表：

- 无。
- 该组接口当前只负责任务调度与结果文件下载，不直接写业务库。

`POST /solver/pbs/abaqus/run`

请求字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `project_id` | `int` | 是 | 项目 ID；用于读取工程 `project_config.pbs` |
| `env` | `string` | 否 | PBS 环境名；未传时使用配置默认值 |
| `input_file` | `string` | 否 | 本地 Abaqus 输入文件完整路径；与 `input_file_name` 二选一，优先级更高 |
| `input_file_name` | `string` | 否 | 输入文件名或项目内相对路径；未传 `input_file` 时使用，按项目 workspace 自动拼接解析 |
| `job_name` | `string` | 否 | PBS 作业名；缺省取输入文件名 |
| `output_dir` | `string` | 否 | 本地结果下载目录；未传时默认下载到输入文件同目录 |
| `wait` | `bool` | 否 | 是否等待远程任务完成，默认 `true` |
| `download_results` | `bool` | 否 | 是否下载结果文件，默认 `true` |
| `poll_interval_sec` | `float` | 否 | 轮询间隔秒数，默认 `10.0` |
| `wait_timeout_sec` | `int` | 否 | 等待远程任务完成的超时秒数，默认 `3600` |
| `timeout_sec` | `int` | 否 | 单次 HTTP 请求超时秒数，默认 `60` |
| `submit_overrides` | `object` | 否 | 提交参数覆盖项，例如覆盖 `CORES/HOSTS/PRECISION` |
| `async_submit` | `bool` | 否 | 是否后台提交，默认 `false` |

返回要点：

- `job_id`
- `remote_job_dir`
- `remote_primary_file`
- `job_status`
- `resolved_job_state`
- `result_files`
- `result_file_paths`
- `downloaded_files`
- `upload`
- `uploaded_result_file`

工程 `project_config.pbs` 至少应提供：

- `env`：可选，默认 PBS 环境名
- `ApplicationId`
- `ApplicationName`
- `VERSION`
- `PLATFORM`
- 可选的 `CORES`、`HOSTS`、`PRECISION`

`POST /solver/pbs/nastran/run`

请求字段与上面一致，但：

- `input_file` / `input_file_name` 解析后的目标文件要求为 `.bdf/.dat/.nas`
- `submit_overrides` 常用于覆盖 `CORES`
- 工程 `project_config.pbs` 中至少应提供 `ApplicationId`、`ApplicationName`、`VERSION`、`PLATFORM`，并可选提供 `CORES`

`POST /solver/pbs/job/status`

请求字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `project_id` | `int` | 是 | 项目 ID；用于读取工程 `project_config.pbs` 并先校验 PBS 配置 |
| `env` | `string` | 否 | PBS 环境名 |
| `job_id` | `string` | 是 | PBS 任务 ID |
| `timeout_sec` | `int` | 否 | 单次状态查询请求超时秒数，默认 `60` |

返回要点：

- `job_id`
- `job_status`
- `resolved_job_state`

补充说明：

- `resolved_job_state` 当前按 PBS 常见状态处理：
  - `Q`：排队中
  - `R`：运行中
  - `C`：完成
  - `F`：失败
- 当 `wait=true` 且最终状态为 `F` 时，接口返回失败。
- 第一版暂不处理多 include 文件、断点续传、失败日志自动解析、任务恢复。
### `POST /correlation/modal/match/frequency_scatter`

接口含义：
基于已经计算好的 `MAC` / `DAC` / 频率误差结果，先按最终唯一模态匹配规则生成匹配模态对，再按“图表散点图友好”的格式返回频率匹配点。

功能说明：
- 该接口复用 `POST /correlation/modal/match` 的最终唯一匹配逻辑，不返回候选集，而是只返回最终匹配成功的模态对。
- 横坐标使用计算模态频率 `freq_fem`。
- 纵坐标使用试验模态频率 `freq_test`。
- 每个散点代表一个最终匹配成功的模态对。
- 返回结构风格对齐现有图表折线接口：
  - `data[0].label`
  - `data[0].xaxis`
  - `data[0].data`
- 同时额外返回 `data[0].points`，用于前端 tooltip 展示更丰富的点位明细。

影响数据表：
- `t_mt_py_fem_modal_correlation`：读，读取已经计算好的模态相关性结果。

请求参数：
| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `mac_threshold` | `float` | 否 | `MAC` 下限，默认 `0.7` |
| `max_freq_error_ratio` | `float` | 否 | 频率相对误差上限，例如 `0.2` 表示 `20%` |
| `method` | `string` | 否 | 匹配方法，当前仅支持 `greedy` |

请求示例：
```json
{
  "project_id": 1002,
  "mac_threshold": 0.7,
  "max_freq_error_ratio": 0.2,
  "method": "greedy"
}
```

返回说明：
- `chart_type`：固定为 `scatter`
- `x_label`：横坐标含义，当前为 `calculated_modal_frequency`
- `y_label`：纵坐标含义，当前为 `test_modal_frequency`
- `data[0].label`：当前散点系列名称，固定为 `matched_modes`
- `data[0].xaxis`：横坐标值列表，字符串形式，便于和现有图表折线结构对齐
- `data[0].data`：散点数组，每项是 `[freq_fem, freq_test]`
- `data[0].points`：散点明细数组，前端可直接用来渲染 tooltip
- `rows`：最终唯一匹配结果的原始行数据，便于前端或调用方复用
- `summary.point_count`：实际返回散点数量
