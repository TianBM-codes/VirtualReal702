# 统一参数响应目录与灵敏度修正方案

## 1. 文档目标

这份文档解决两个实际问题：

1. 灵敏度计算和真正模型修正不是同一个阶段，参与的参数集合可能不同。
2. 静力响应、动力响应、后续模态 `MAC` 响应，希望尽量统一管理，而不是分散在多套“各管各的”目录里。

这次落地后的总思路是：

- `t_mt_py_fem_modal_correlation` 继续只做模态匹配候选池。
- `t_mt_py_fem_selected_parameter` 升级为统一正式参数目录。
- `t_mt_py_fem_response_catalog` 升级为统一正式响应目录。
- 不同求解流程只从统一目录里过滤自己需要的参数和响应。

## 2. 参数目录设计

### 2.1 表定位

`t_mt_py_fem_selected_parameter` 继续作为正式参数表，但新增“用途范围”语义。

### 2.2 新增字段

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `usage_scope` | `JSON` | 否 | 参数用途范围；为空时兼容旧数据，默认按 `["SENSITIVITY", "UPDATE"]` 处理 |

### 2.3 推荐取值

```json
["SENSITIVITY"]
```

```json
["UPDATE"]
```

```json
["SENSITIVITY", "UPDATE"]
```

### 2.4 业务含义

- `SENSITIVITY`：该参数参与灵敏度计算。
- `UPDATE`：该参数参与真正模型修正。

这就能支持下面的流程：

1. 先创建一批候选参数。
2. 用这些参数做灵敏度计算。
3. 根据灵敏度结果，只把高灵敏度参数标记为 `UPDATE`。
4. 后续模型修正只读取带 `UPDATE` 的参数。

### 2.5 当前新增接口

#### `POST /optimization/parameter/usage/update`

接口含义：批量更新正式参数目录中的用途范围。

影响数据库：

- `t_mt_py_fem_selected_parameter`：写，更新 `usage_scope`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `parameters` | `array` | 是 | 要更新的参数列表 |
| `parameters[].parameter_name` | `string` | 是 | 参数名 |
| `parameters[].usage_scope` | `string[]` | 是 | 参数用途范围，只允许 `SENSITIVITY`、`UPDATE` |

请求示例：

```json
{
  "project_id": 3,
  "parameters": [
    {
      "parameter_name": "T_101",
      "usage_scope": ["SENSITIVITY", "UPDATE"]
    },
    {
      "parameter_name": "T_102",
      "usage_scope": ["SENSITIVITY"]
    }
  ]
}
```

#### `POST /optimization/parameter/select_for_update`

接口含义：把一批参数加入“模型修正参数集合”。

影响数据库：

- `t_mt_py_fem_selected_parameter`：写，给所选参数增加 `UPDATE`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `parameter_names` | `string[]` | 是 | 需要进入模型修正的参数名列表 |
| `replace_update_set` | `bool` | 否 | 是否用本次选择覆盖旧的 `UPDATE` 集合，默认 `false` |

请求示例：

```json
{
  "project_id": 3,
  "parameter_names": ["T_101", "E_201"],
  "replace_update_set": false
}
```

#### `POST /optimization/parameter/remove_from_update`

接口含义：把一批参数从“模型修正参数集合”中移除。

影响数据库：

- `t_mt_py_fem_selected_parameter`：写，移除 `UPDATE`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `parameter_names` | `string[]` | 是 | 需要移除的参数名列表 |

请求示例：

```json
{
  "project_id": 3,
  "parameter_names": ["T_102"]
}
```

## 3. 响应目录设计

### 3.1 表定位

`t_mt_py_fem_response_catalog` 升级为统一正式响应目录。

它保存的是“当前项目正式选中的响应”，而不是候选结果。

### 3.2 新增字段

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `TINYINT(1)` | 否 | 响应是否启用，默认 `1` |
| `selection_source` | `VARCHAR(64)` | 否 | 响应来源，例如 `manual_modal_match`、`auto_modal_match` |
| `solver_scope` | `JSON` | 否 | 响应面向的求解流程范围 |
| `updated_at` | `DATETIME` | 否 | 最后更新时间 |

### 3.3 `solver_scope` 推荐取值

```json
["DSA"]
```

```json
["SOL200", "BAYESIAN"]
```

### 3.4 当前支持的响应类型

- `STATIC_DISPLACEMENT`
- `STATIC_STRESS`
- `STATIC_STRAIN`
- `MODAL_FREQUENCY`
- `MODAL_MAC`

### 3.5 当前新增接口

#### `POST /optimization/response/catalog`

接口含义：查询统一正式响应目录。

影响数据库：

- `t_mt_py_fem_response_catalog`：读，返回统一正式响应目录

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |

请求示例：

```json
{
  "project_id": 3
}
```

#### `POST /optimization/response/modal_frequency/options`

接口含义：查询模态频率正式响应候选项。

影响数据库：

- `t_mt_py_fem_modal_result`：`response_source="FEM"` 时读，返回 FEM 计算模态频率。
- `t_mt_py_fem_modal_correlation`：`response_source="TEST"` 时读，按唯一匹配规则恢复试验模态频率候选。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `response_source` | `string` | 是 | `FEM` 或 `TEST` |

请求示例：

```json
{
  "project_id": 3,
  "response_source": "FEM"
}
```

返回结构说明：

- `FEM`：表格列为“阶次、频率(Hz)”
- `TEST`：表格列为“试验频率、试验阶次、计算频率、计算阶次”
- 返回结构对齐现有表格型接口，核心字段为 `columns`、`rows`、`summary`

#### `POST /optimization/response/modal_match/select`

接口含义：把用户手工选中的模态匹配对，正式写入响应目录。

影响数据库：

- `t_mt_py_fem_modal_correlation`：读，校验所选 `(test_mode_no, fem_mode_no)` 是否存在，并取出 `MAC`、频率等信息
- `t_mt_py_fem_response_catalog`：写，保存正式模态响应

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `overwrite` | `bool` | 否 | 是否覆盖当前项目中相同响应类型的旧记录，默认 `false` |
| `response_types` | `string[]` | 是 | 生成哪些模态响应，当前支持 `MODAL_FREQUENCY`、`MODAL_MAC` |
| `solver_scope` | `string[]` | 否 | 响应面向的求解流程，默认 `["SOL200", "BAYESIAN"]` |
| `scatter` | `float` | 否 | 响应离散度，默认 `0.05` |
| `selected_pairs` | `array` | 是 | 用户选中的模态对列表 |
| `selected_pairs[].test_mode_no` | `int` | 是 | 试验模态号 |
| `selected_pairs[].fem_mode_no` | `int` | 是 | FEM 模态号 |

请求示例：

```json
{
  "project_id": 3,
  "overwrite": false,
  "response_types": ["MODAL_FREQUENCY"],
  "solver_scope": ["SOL200", "BAYESIAN"],
  "scatter": 0.05,
  "selected_pairs": [
    {
      "test_mode_no": 1,
      "fem_mode_no": 2
    },
    {
      "test_mode_no": 3,
      "fem_mode_no": 4
    }
  ]
}
```

#### `POST /optimization/response/modal_frequency/create_from_match`

接口含义：按当前筛选条件自动生成一批推荐模态频率正式响应。

影响数据库：

- `t_mt_py_fem_modal_correlation`：读，读取已计算的模态相关性结果
- `t_mt_py_fem_response_catalog`：写，保存自动生成的模态频率正式响应

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_id` | `int` | 是 | 项目 ID |
| `overwrite` | `bool` | 否 | 是否覆盖旧的 `MODAL_FREQUENCY` 正式响应，默认 `true` |
| `mac_threshold` | `float` | 否 | `MAC` 下限；支持 `0~1` 或 `0~100` 两种写法 |
| `max_freq_error_ratio` | `float` | 否 | 最大频率相对误差，例如 `0.15` 表示 `15%` |
| `solver_scope` | `string[]` | 否 | 响应面向的求解流程，默认 `["SOL200", "BAYESIAN"]` |
| `matching_method` | `string` | 否 | 当前只支持 `greedy` |
| `scatter` | `float` | 否 | 响应离散度，默认 `0.05` |

请求示例：

```json
{
  "project_id": 3,
  "overwrite": true,
  "mac_threshold": 80,
  "max_freq_error_ratio": 0.15,
  "solver_scope": ["SOL200", "BAYESIAN"],
  "matching_method": "greedy"
}
```

## 4. 模态匹配候选池

`t_mt_py_fem_modal_correlation` 的定位不变：

- 它只保存候选 `(test_mode_no, fem_mode_no)` 配对及其相关性指标。
- 它不是正式响应表。
- 用户真正选中的模态对，要单独写入 `t_mt_py_fem_response_catalog`。

## 5. 各流程如何消费

### 5.1 DSA / 灵敏度计算

读取：

- 参数：`usage_scope` 包含 `SENSITIVITY`
- 响应：`solver_scope` 包含 `DSA`

### 5.2 SOL200

读取：

- 参数：
  - 灵敏度阶段读 `SENSITIVITY`
  - 修正阶段读 `UPDATE`
- 响应：
  - `solver_scope` 包含 `SOL200`
  - `response_type` 属于 `MODAL_FREQUENCY` / `MODAL_MAC`

### 5.3 Bayesian 模态修正

读取：

- 参数：`usage_scope` 包含 `UPDATE`
- 响应：
  - `solver_scope` 包含 `BAYESIAN`
  - `response_type` 属于 `MODAL_FREQUENCY` / `MODAL_MAC`

## 6. 第一批实现边界

为了不打断现有使用方式，当前程序改造采用“增量接入”：

- 保留旧接口继续可用
- 新接口先补齐
- 新字段先开始落库和回传
- 下游流程先在参数和响应过滤点接入新语义

这样开发者本地 `git pull` 后可以逐步切换，不需要一次性重做全部前端逻辑。
