# 近期试验与仿真接口汇总

更新日期：2026-10-22。以当前路由、请求模型和服务实现为准。
本页汇总最近新增或调整的四个接口，全部使用 POST + JSON，请求路径没有额外的 `/api` 前缀。

## 1. 接口速查

| 路径 | 用途 | 数据来源 | 返回重点 |
| --- | --- | --- | --- |
| `/import/test_load_level` | 下载并解析试验 TXT，保存读数及文件信息 | 下载链接或服务器本地 TXT | 导入数量、元数据 |
| `/get/sensor_load_level_curve` | 查询一个试验测点的加载级曲线 | MySQL 加载级试验数据表 | 曲线列表 `data` |
| `/get/sensor_node_history` | 查询已匹配测点的 ODB 方向投影结果 | 原始 ODB，需 Abaqus Python | 各 step/截面点曲线、匹配节点、异常信息 |
| `/get/simright_test_load_level_comparison` | 默认返回示例表格与对比曲线；可显式切换真实查询 | 默认读取示例 JSON，真实分支读取 TXT 入库数据和数巧 | `table`、`curves`、下拉选项、示例标记 |

旧路径 `/get/sensor_curve` 已改名，不再使用。

## 2. 公共响应与曲线结构

成功信封：

```json
{"ok": true, "code": 200, "message": "成功", "data": {}}
```

下文提到的返回字段都位于外层 `data` 内。
曲线结构统一沿用 `/sensitivity/stored/curve/parameter`：

```json
{
  "label": "测点名称-试验",
  "xaxis": ["0", "1", "2"],
  "data": [["0", 0.0], ["1", 12.5], ["2", null]]
}
```

`xaxis` 为字符串数组，`data` 为 `[横坐标, 读数]` 数组。缺失或提取失败用 `null`，不补零。
单独曲线接口的列表在外层响应 `data.data`，综合对比接口的列表在 `data.curves`。

当前 `webapi.common.error_response` 将路由捕获的业务错误统一包装为 HTTP 500、`ok=false`、`code=500`。
原始状态在 `error.details.original_status_code`，例如数据已更新是 409、数巧服务错误是 502。
请求模型校验失败由 FastAPI 处理，通常是 HTTP 422；不要把它和上述业务错误混为一类。
请求返回 `ok=true` 时仍需检查 `issues`，它可能包含部分仿真点提取失败的原因。

完整业务错误示例（HTTP 500）：

```json
{
  "ok": false,
  "code": 500,
  "message": "试验 TXT 已更新，请刷新表格后重新选择仿真 step",
  "data": null,
  "error": {
    "code": "CONFLICT",
    "message": "试验 TXT 已更新，请刷新表格后重新选择仿真 step",
    "details": {"original_status_code": 409}
  }
}
```

以下成功响应均为结构示例，测点、数值、时间、文件摘要及记录数量仅用于说明。
示例中的小数组不代表实际 TXT 只有几个测点或记录；实际返回完整数据，不截断。

## 3. 下载并导入 TXT

`POST /import/test_load_level`

```json
{
  "project_id": 2026101601,
  "file_path": "D:\\WorkSpace\\WebThreeJS\\PyModel2JsonDataFolder\\test_data\\AT-2_lire.txt",
  "ignore_last_reading": true
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `project_id` | 是 | 外部提供的正整数工程 ID，不从文件推断 |
| `file_path` | 是 | HTTP/HTTPS 下载链接，或服务器本地路径 |
| `work_condition_id` | 否 | 字符串，最长 100 字符，工况标识 |
| `measurement_id` | 否 | 字符串，最长 100 字符，测量标识 |
| `ignore_last_reading` | 否 | 默认 true，排除每个测点最后一个读数 |
| `axis_label` | 否 | 默认使用 TXT 中第一行加载信息的名称 |
| `unit` | 否 | 显式指定单位；不传时尝试从文件头读取 |

返回 `project_id/work_condition_id/measurement_id/sensor_count/sample_count/row_count/metadata`。
实际测试 TXT 包含 80 个测点，每点 19 个原始读数；末值排除后对应 18 条记录，共 1440 条有效读数。

保存位置：

- 测点读数：`t_mt_py_test_load_level_data`。
- 动态加载信息、表头、日期、页信息及文件摘要等：`t_mt_py_project_config.extra_json.test_load_level_import`。
- 指定工况或测量时，元数据改为 `extra_json.test_load_level_imports[work_condition_id][measurement_id]`，省略的一侧用空字符串键，防止不同文件的横轴覆盖。
- 动态加载信息结构：`axis_rows: [{label, value}]`，不固定名称或行数。
- 被排除的末值：元数据中的 `ignored_trailing_values`。
- 原文件：工程目录的 `test_data/load_level/<导入标识>/source.txt`。

下载和解析完成后，读数与元数据在同一事务内替换。重新导入成功只替换同一项目、工况、测量下的试验数据，其他组不变，失败保留旧数据。新增的两个数据库字段为 `VARCHAR(100) NOT NULL DEFAULT ''`，唯一索引包含这两个标识。省略、null、空字符串均表示历史默认组，不代表查询全部工况。
TXT 按 `sample_index` 保存原始记录顺序，重复加载值、下降及回零均可保留。

```json
      "page_axes": [{
        "级别": [0, 1, 0],

```

| 返回字段 | 类型 | 含义 |
| --- | --- | --- |
| `data.sensor_count` | integer | 导入的测点数量 |
| `data.sample_count` | integer | 每个测点的有效记录数，不含被排除的末值 |
| `data.row_count` | integer | 写入读数表的总记录数 |
| `data.metadata` | object | 保存到项目 `extra_json.test_load_level_import` 的完整元数据 |
| `metadata.axis_rows` | array | 动态加载信息行，保留名称、值和顺序，数量不固定 |

| `metadata.page_axes` | object[] | 每页解析出的加载信息 |
| `metadata.ignored_trailing_values` | object | 测点名称到被排除末值的对应关系 |

`imported_at` 带时区，示例为 UTC；`start_datetime` 来自试验文件，可能为空且没有时区。
`unit` 无法识别时为 null。当前解析失败会使整个导入失败，不会返回部分成功；
`except_gauges/broken_gauge` 属于解析器保留字段，不代表当前已经实现了全部损坏测点诊断。

## 4. 查询单测点试验曲线

`POST /get/sensor_load_level_curve`

```json
{"project_id": 2026101601, "sensor": "310004a", "work_condition_id": "condition-001", "measurement_id": "measurement-001"}
```

`project_id`、`sensor` 必填；新增 `work_condition_id`、`measurement_id` 为可选字符串，最长各 100 字符，与导入时的标识一致。查询同时精确匹配项目、测点、工况、测量；省略或 null 对应数据库空字符串，仅查询历史默认组。返回 `project_id/sensor/work_condition_id/measurement_id/curve_type/data/unit/axis_label/source/summary`，曲线格式不变。
TXT 数据使用导入时选定的横轴并保留原始记录顺序；旧 CSV 数据按加载值排序。
没有对应读数时返回空曲线列表，不生成演示值。

### 4.1 成功返回示例

```json
{
  "ok": true,
  "code": 200,
  "message": "传感器曲线获取成功",
  "data": {
    "project_id": 2026101601,
    "sensor": "310004a",
    "work_condition_id": "condition-001",
    "measurement_id": "measurement-001",
    "curve_type": "sensor",
    "data": [{
      "label": "310004a",
      "xaxis": ["0", "1", "0"],
      "data": [["0", 0], ["1", 10], ["0", 1]]
    }],
    "unit": "με",
    "axis_label": "级别",
    "source": "t_mt_py_test_load_level_data",
    "summary": {"curve_count": 1, "point_count": 3}
  }
}
```

| 返回字段 | 类型 | 含义 |
| --- | --- | --- |
| `data.data` | array | 该测点的曲线列表，有读数时为一条 |
| `data.unit` | string/null | 读数单位 |
| `data.axis_label` | string/null | TXT 默认横轴名；旧 CSV 记录通常为空 |
| `data.summary.curve_count` | integer | 曲线条数 |
| `data.summary.point_count` | integer | 点的数量，含明确存储为 null 的读数 |

无读数时仍返回成功：`data.data=[]`、`summary={"curve_count":0,"point_count":0}`，
`unit/axis_label` 为 null，`source` 仍为上述表名。

## 5. 查询 ODB 方向投影曲线

`POST /get/sensor_node_history`

```json
{
  "project_id": 2026101601,
  "sensors": [{"name": "DEMO_P01", "direction": [1, 0, 0]}],
  "fields": "S",
  "result_group": "default_result"
}
```

- `sensors` 至少一个，每个元素需要名称和非零三维方向，名称不能重复。
- `fields` 是单个字符串，支持 `U/S/E/LE`，默认 `U`，不接受数组。
- `result_group` 可选，优先采用 `default_result`，否则工程必须只有一个结果组。
- 读取已有匹配关系，不重新匹配节点；测量方向为有限元全局方向，服务端单位化。
- 所有 step/frame 均保留，每个测点、step、截面点分别成曲线，横轴为 ODB 的 `frame_value`。
- `U` 是位移方向投影；`S/E/LE` 是张量方向投影。应变缺少 E 时可回退 LE。
- 返回 `data` 曲线列表、`matches`、`actual_fields`、`issues` 和统计信息。

`DEMO_P01` 属于此前建立的示例节点匹配；从 TXT 导入的 `310004a` 等测点不会自动获得有限元节点匹配关系。
该接口读取原始 ODB，需要配置 `APP_ABAQUS_CMD`；与数巧服务相互独立。

### 5.1 成功返回示例

```json
{
  "ok": true,
  "code": 200,
  "message": "测点节点时程获取成功",
  "data": {
    "project_id": 2026101601,
    "result_group": "default_result",
    "fields": "S",
    "curve_type": "sensor_node_history",
    "actual_fields": ["S"],
    "data": [
      {
        "label": "DEMO_P01|Step-15-30|S",
        "xaxis": ["0.0", "1.0"],
        "data": [["0.0", 0], ["1.0", 0.64]]
      },
      {
        "label": "DEMO_P01|Step-90-30|S",
        "xaxis": ["0.0", "1.0"],
        "data": [["0.0", 0.64], ["1.0", -12.39]]
      },
      {
        "label": "DEMO_P01|Step-90|S",
        "xaxis": ["0.0", "1.0"],
        "data": [["0.0", -12.39], ["1.0", -13.03]]
      }
    ],
    "matches": [{
      "name": "DEMO_P01",
      "coordinates": [15, 3.75, 0],
      "direction": [1, 0, 0],
      "match": {
        "instance_name": "PART-ZHIJIA-1",
        "part_name": "PART-ZHIJIA",
        "node_label": 2,
        "node_coordinates": [15, 3.75, 0],
        "distance": 0
      }
    }],
    "issues": [],
    "direction_coordinate_system": "global",
    "summary": {"sensor_count": 1, "curve_count": 3}
  }
}
```

| 返回字段 | 类型 | 含义 |
| --- | --- | --- |
| `data.fields` | string | 请求的单个字段名 |
| `data.actual_fields` | string[] | 实际使用的字段；请求 E 时可能包含 LE |
| `data.data` | array | 每个测点、step、截面点的方向投影曲线 |
| `data.matches` | array | 测点坐标、全局测量方向及有限元匹配节点信息 |
| `matches[].match.distance` | number/null | 之前匹配时保存的距离，不在本次重新计算 |
| `data.issues` | array | 提取异常，正常时为空 |

有壳截面点时，label 末尾附加 `|截面点描述`。各 step 横轴独立，未拼接成全局时间。
字段缺失或投影失败的帧用 null 占位，`issues` 的元素示例：

```json
{
  "sensor": "DEMO_P01",
  "step": "Step-15-30",
  "frame_idx": 1,
  "status": "projection_failed",
  "message": "坐标变换失败的具体原因"
}
```

`status` 还可能是 `missing_field`、`missing_node_data`、`extraction_failed`。
某些异常没有详细原因时，`message` 为 null。

## 6. SimRight 表格与对比曲线

`POST /get/simright_test_load_level_comparison`

请求使用 `Content-Type: application/json`。所有参数放在 JSON 请求体中。
已移除请求参数 `filename`、`step_mapping`；`sensors` 每项只允许 `name`。

### 请求参数与两种用途

| 参数 | 类型/默认值 | 说明 |
| --- | --- | --- |
| `project_id` | 正整数，必填 | 外部传入的项目 ID |
| `work_condition_id` | 字符串，可省略或为 null，最长 100 字符 | 真实模式精确筛选试验数据的工况；示例模式不筛选示例文件 |
| `measurement_id` | 字符串，可省略或为 null，最长 100 字符 | 真实模式精确筛选试验数据的测量；示例模式不筛选示例文件 |
| `example_mode` | bool，默认 true | true 读取示例文件；false 查询数据库和数巧 |
| `sensors` | 对象列表，可省略或为 null | 如 `[{"name":"310004a"}]`；省略、null、空列表均只返回加载信息和 step 下拉列，不返回测点列或曲线 |
| `steps` | step ID/null 列表，可省略 | 每个位置对应一条试验加载记录；省略或 null 时全部未选择；显式列表长度必须等于有效记录数 |
| `simright_base_url` | URL，可省略 | 真实模式的数巧地址；省略时读取项目配置 `simright.base_url` |
| `profile` | markdown/excel，默认 markdown | 数巧客户端协议配置 |
| `axis_label` | 字符串，可省略 | 默认采用 TXT 导入时的横轴；可切换为其他加载信息行 |
| `shell_layer` | 字符串，默认 bottom | 数巧壳层 |
| `import_sha256` | 字符串，可省略 | 真实模式校验 TXT 是否已重新导入，防止记录错位 |

`steps` 替代原来的 `step_mapping`。例如 `[42, null, 91]` 表示第 1 条试验记录选 step 42，第 2 条未选择，第 3 条选 step 91。ID 取 `table` 中 `key=simright_step` 列的 `selectOptions[].value`，不是选项数组下标。JSON 中使用 `null`，对应 Python 的 `None`。

只提取用户选择的 step。真实模式对每个节点和变量取该 step 返回的最大 `stateId`；相同 step、节点和变量在单次请求内复用结果。未选择的位置仿真值为 null，试验读数保留。选择关系由每次请求传入，不在数据库中持久化。

### 示例模式：先取表头，再取指定测点曲线

当前默认示例模式，不访问 MySQL 或数巧。示例可在 [simright_load_level_comparison.json](../../tools/examples/simright_load_level_comparison.json) 中修改。
文件中的“上xx、下xx”属于动态加载信息，与测点 `310004a`、`310005a` 分开保存；示例有效记录数为 4。

首次请求：

```json
{"project_id": 2026101601}
```

返回完整成功信封示例（示例来源字段和 summary 等也保留）：

```json
{

    "axis_label": "载荷",

    "table": [
      {"key": "axis:0", "label": "载荷", "value": [0, 1, 2, 3]},
      {"key": "axis:1", "label": "上xx", "value": [0, 10, 20, 30]},
      {"key": "axis:2", "label": "下xx", "value": [0, -8, -16, -24]},
      {
        "key": "simright_step", "label": "仿真step", "type": "select",
        "selectOptions": [
          {"label": "下拉1", "value": 0}, {"label": "下拉3", "value": 1},

    "summary": {"sample_count": 4, "sensor_count": 0, "curve_count": 0}
```

用户选择 step 后调用同一接口：

```json
{
  "project_id": 2026101601,
  "sensors": [{"name": "310004a"}, {"name": "310005a"}],
  "steps": [0, null, 2, 3]
}
```

此时 `data.table` 仍只包含动态加载信息列和 step 下拉列。测点的试验、仿真读数统一放在 `data.curves`，不再以 `test:*` 或 `simulation:*` 列重复返回。本次选择两个测点，因此返回四条曲线。下面展示其中一个测点对应的两条曲线：

```json
[
  {
    "label": "310004a-试验",
    "xaxis": ["0", "1", "2", "3"],
    "data": [["0", 0], ["1", 10], ["2", 20], ["3", 30]]
  },
  {
    "label": "310004a-仿真",
    "xaxis": ["0", "1", "2", "3"],
    "data": [["0", 0], ["1", null], ["2", 19.5], ["3", 29.5]]
  }
]
```

示例模式也会校验名称、steps 长度和 step ID，并根据用户选择提取示例值；不会随意给未知测点生成假曲线。示例仿真数组按 step 选项顺序提供数值，所有示例 step 必须有对应值。

### 真实模式与服务端项目配置

真实模式先通过 `/import/test_load_level` 导入 TXT，再调用本接口。每次真实请求都需要 `example_mode: false`。

```json
{
  "project_id": 2026101601,
  "example_mode": false,
  "sensors": [{"name": "310004a"}],
  "steps": [42, null, 91]
}
```

这里假设真实 TXT 有 3 条有效记录；实际长度应按首次响应的 `record_indices` 确定。首次只获取表头时省略 `sensors`、`steps` 即可。

模型标识不再由对比请求传入。使用现有 `POST /project/config` 配置，保存到 `t_mt_py_project_config.extra_json.simright`：

```json
{
  "project_id": 2026101601,
  "extra_json": {
    "simright": {
      "base_url": "http://simright-server:8080",
      "filename": "project/model.rdb",
      "instance_parts": {
        "PART-1-1": {"part_id": 5, "part_ori_id": 4}
      },
      "sensor_bindings": {
        "310004a": {
          "quantity": "scalar",
          "var_name": "E.EL.11",
          "simulation_scale": 1000000
        }
      }
    }
  }
}
```

配置示例需替换为实际地址、数巧模型标识、实例、零件及变量名。更新 `simright` 时应提交该块完整配置，项目配置合并规则不会递归合并其内部字段。

- 按 `project_id + name` 查询 `t_mt_py_fem_node_match`，使用 `fem_node_label`；实例通过 `instance_parts` 映射到数巧零件，不能直接把实例名当作 part ID。
- `sensor_bindings` 配置每个测点的结果变量、投影与单位换算；也允许在服务端明确配置 `node_id`、`part_id`、`part_ori_id`，适用于数巧节点编号与本地模型不同的情况。显式节点配置优先。
- `part_id` 是内部 ID，`part_ori_id` 是过滤用的 oriId；配置 oriId 时必须同时配置内部 ID。未配置零件时，仅在结果中的节点没有零件歧义时允许返回。
- 标量查询需要 `quantity=scalar` 和 `var_name`。张量查询配置 `quantity=stress/strain`、全局 `direction`；应变还需要 `shear_convention=tensor/engineering`。`component_vars` 可映射六分量，默认使用 `S.EL.*` / `E.EL.*`。
- `simulation_scale` 默认 1，不自动换算单位。试验与仿真单位必须一致，例如应变转微应变可以配置 1000000。
- 缺少模型配置、匹配或变量设置时明确报错；全部未选 step 时不查询节点结果或解析节点绑定。

### 响应与错误约定

曲线格式仍为 `{label, xaxis, data:[[x,y],...]}`，放在 `data.curves`。`table` 每个对象表示一列，所有 `value[i]` 对应同一条试验记录，加载信息列数量不固定。
`summary.sensor_count` 是本次返回的测点数；不传 sensors 时为 0。每个选定测点返回两条曲线，即使仿真值全部为 null。
未选择 step 不产生 issue；选择后单点提取失败会保留试验值、将仿真值设为 null，并在 `issues` 中记录测点、记录序号与原因。成功提取的零件和帧保存在 `resolved_states`。数巧工况请求整体失败时返回错误。

请求中的旧 `filename`、`step_mapping` 或 sensors 内的 `node_id` 等额外字段会触发请求模型校验错误（HTTP 422）。服务业务错误沿用本文开头说明的 HTTP 500/业务码 500 信封，原始状态保存在 `error.details.original_status_code`。真实数巧服务尚未联调。
